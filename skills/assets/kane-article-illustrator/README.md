# kane-article-illustrator

为已有文章制作插图：分析哪里值得配图，制定具体方案，统一画风，编写逐图提示词，调用当前可用的生图工具，并查看实际成图。支持按需另存带图片的 Markdown 副本，默认保留原稿。

## 使用

在支持技能的 Agent 中按名称调用；Codex 中可输入 `$kane-article-illustrator`。技能没有关闭自动选择，是否自动触发取决于运行时。

```text
用 kane-article-illustrator 给 notes/缓存设计.md 制作正文插图，风格简洁，直接生成。
为这篇文章先做配图方案，列出位置、图意和推荐风格，等我确认再生成。
只写这篇文章的配图提示词，使用手绘讲解风格，不生成图片。
沿用上次方案，只重做第 2 张图；完成后另存一份带图片的 Markdown。
```

这些是自然语言请求示例，本技能不提供斜杠命令解析器或生图 CLI。

## 输入

- 可读的文章文件或粘贴正文；节选可以单独处理，但不会被补写成全文。
- 可选参考图、数量、指定位置、风格、配色、比例、图中文字语言、输出目录与生图工具。
- 可选要求将图片插入文章；默认只交付配图产物，需要插入时另存副本。

仅提供标题、链接或摘要不足以制作忠实于全文的插图，需要正文。技能以正文配图为主，不改写文章，不代替发布或网页排版。

## 三种执行范围

| 范围 | 交付 | 是否生图 |
| --- | --- | --- |
| 只做方案 | 正文快照、配图位置、图意、类型、统一视觉规范及计划文件 | 否 |
| 只写提示词 | 方案和可独立使用的逐图提示词 | 否 |
| 完整出图 | 方案、提示词、实际图片或工具原生结果、逐图验收记录 | 是，需要可用工具 |

“给文章配图”“制作插图”默认完整出图；“先给方案，等我确认”会停在方案阶段。已经明确的要求不重复询问，也不会强制每章配一张图。

## 工作方式

1. 阅读文章，找出概念、流程、对比、结构、时间演进或场景中适合视觉表达的信息。
2. 为每张图记录原文依据、具体目的、可定位的段落锚点、画面内容、比例、标签与文件名。
3. 统一配色、线条、人物与字体气质，按图形类型组织各张构图。内置手绘讲解、扁平矢量感、编辑插画、技术蓝图和水彩叙事，也支持自定义描述或参考图。
4. 先保存提示词，再生成一张基准图并查看，后续图片延续视觉规范。
5. 逐张核对含义、文字、数字、箭头、裁切与一致性；默认每张初次生成后最多再尝试一次，失败只处理该项。
6. 交付当前成果和状态；需要时把验收通过的本地图片插入 Markdown 副本并验证相对路径。

## 文件交付

文章文件的默认输出目录是文章同级 `illustrations/<文章文件名去扩展名>/`；粘贴正文使用工作目录下 `illustrations/<主题短名>/`。用户可指定位置，新任务的目录冲突采用未占用编号名。

```text
illustrations/<文章名>/
  source.md
  plan.md
  prompts/01-topic.md
  images/01-topic.png
```

只创建当前执行范围需要的文件；图片扩展名以工具真实输出为准。提示词、计划记录和图片可用于后续单张修改，更新另存版本，不覆盖旧成果。

插图副本默认与原文章同目录，命名为 `<文章名>-illustrated.md`，粘贴正文则保存在本次输出目录。图片路径相对实际副本计算，原文已有配图默认保留。

没有本地文件系统或图片工具只返回原生结果时，会在对话中交付可用成果并说明限制，不虚构文件路径。只有真实可读的本地图片才能写入 Markdown 副本；部分失败或未验收项不会作为占位图插入。

## 依赖与限制

- 技能包可单独复制，内含所需规则与参考文档，不依赖本仓库其他技能、私人目录、Bun 或自带脚本。
- 完整出图依赖运行时已有的生成工具或用户已配置并授权的后端；优先尊重指定工具，否则选择可用原生工具。不会自动安装服务或扫描密钥。
- 没有生图工具时仍可交付方案与提示词，但会明确图片未生成。没有视觉查看能力时只能标记“已生成未验收”。
- 准确文字、数字与复杂关系需要逐图核对，超出修正次数时保留问题记录；不会用通用图片或提示词文件冒充合格插图。
- 图像“矢量感”是画风，不保证输出矢量文件；图像尺寸、格式、透明度及参考图能力取决于所用工具。
