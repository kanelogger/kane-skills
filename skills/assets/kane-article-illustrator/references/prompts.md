# 提示词编写

逐图保存一份可复用的提示词，不依赖“同上”“沿用上一张”或未随请求传入的上下文。提示词语言按工具能力选择，图内可见文字的语言和精确内容单独声明。

## 文件与模板

文件名采用稳定编号和简短主题，如 `01-cache-flow.md`。这里是文件内容约定，不是可直接执行的 CLI 参数。

```markdown
# 01 缓存读取流程

## 文章依据与目的
来源锚点、支撑原句、这张图需要帮助读者理解的一个问题。

## 生成提示词
图形类型与表达目标：
具体主体与动作：
构图和分区：
元素及关系（包含方向、顺序、分支或对比维度）：
必须显示的文字和数据（逐项列出；无文字时写“无”）：
统一风格、配色、线条、人物或主体特征：
比例、留白与边距：
参考图及用途（只有实际可访问的图片才列工具输入）：
不得出现的无关元素、额外文字或错误关系：

## 验收要点
本图需要逐项核对的文字、数字、关系和构图要求。
```

依据和验收要点用于追溯；工具实际接收“生成提示词”及必要参考图。按实际工具填写尺寸、参考图等参数，不把整个 Markdown 文件、模板标题或内部编号当成要画的文字。

## 按类型补充

- **概念图**：列主体、组成、视觉映射与不能误解的边界。隐喻需在图注中说明时同步记录，不暗示它是真实照片或测量结果。
- **流程图**：逐一列出节点和有向连接；区分成功、失败、条件和回路。对未给出的分支留白或提问，不自行补齐业务逻辑。
- **对比图**：两侧对象使用同一组维度和相当的视觉权重。没有定量依据时不画比例柱、百分比或精确坐标。
- **框架图**：分别写明包含、依赖、协作等关系；多种线型要给图例，不把所有连接都画成单向箭头。
- **时间线**：列原文日期和事件；顺序示意与按时间比例绘制明确区分，未知时间不推算成事实。
- **场景图**：列一个视觉焦点、具体动作、环境和情绪；文字可以省略，避免把文章小标题全部塞进画面。

## 文字与事实

图内文字采用允许显示的清单，要求模型不要额外生成标题、图例或长段落。专有名词、数字、单位和大小写按文章逐项列出；色值、风格名与提示词分区标题只是绘制指引，不得画入成图。

标签用必要的短语，避免依靠过小文字承载正文。数字、箭头或公式是解释核心且工具难以可靠绘制时，先简化画面；仍不能保证时报告需要精确制图的部分，不拿近似图冒充准确结果。

参考图内容与文章冲突时，文章事实优先，参考只用于用户指定的视觉维度。用户明确要求示意数据时逐项标明“示意”，与文章真实数据区分。

## 单张修改

修正提示词保留原图的目的、视觉规范和已正确的内容，只指出需修改的元素及期望关系。工具支持编辑时传入实际原图；不支持时使用完整提示词重画。新版本记录对应旧图及修改原因，不覆盖旧提示词。
