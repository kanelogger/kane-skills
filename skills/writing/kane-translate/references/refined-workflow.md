# 翻译工作流程细节

## 目录

- 步骤 1：内容分析
- 步骤 2：组装翻译提示词
- 步骤 3：初稿
- 步骤 4：批判性审校
- 步骤 5：修订
- 步骤 6：润色
- 子 agent 的职责
- 分块 refined 翻译

本文件为每个工作流步骤提供详细指引。各步骤在各模式间共享：

- **Normal**（默认）：步骤 1（分析）→ 步骤 2（组装提示词）→ 翻译并保存 `{source-filename}`
- **Refined**：步骤 1（分析）→ 步骤 2（组装提示词）→ 步骤 3（初稿）→ 步骤 4（审校）→ 步骤 5（修订）→ 步骤 6（润色）
- **Normal → 升级**：normal 模式完成后，保留当前译文为 `03-draft.md`，继续执行步骤 4 → 步骤 5 → 步骤 6

`{source-filename}` 为源文件的完整文件名（含扩展名）。所有中间结果都以文件形式保存在输出目录中；若与最终文件重名，冲突的中间文件按入口规则加 `work-` 前缀，以下引用同步替换。

## 步骤 1：内容分析

翻译之前，先分析源材料。把分析结果保存为输出目录中的 `01-analysis.md`。

### 1.1 内容摘要

- 这份内容讲什么？核心论点是什么？
- 作者背景、立场与写作语境
- 原文的目的与目标读者

### 1.2 术语

- 列出技术术语、专有名词、品牌名、缩写
- 与已加载的术语表交叉核对
- 对术语表中没有的词，确定标准译法
- 记录到术语表中

### 1.3 语气与风格

- 正式还是口语？有无幽默、比喻、文化引用？
- 结合目标读者，译文应采用什么语域？

### 1.4 翻译难点

找出翻译中可能造成困难的地方：

- **理解缺口**：目标读者可能不理解的术语或引用——注明需要什么解释
- **比喻性语言**：无法直译的比喻、习语、说法——注明其本意及在目标语言中的处理方式（意译／替换／保留）
- **结构难点**：长而复杂的句子、文字游戏、双关或需要创造性适配的幽默

**保存 `01-analysis.md`**，结构如下：
```
## 内容摘要
[核心论点、作者、语境、目的]

## 术语
[术语 → 译法, ...]

## 语气与风格
[评估]

## 翻译难点
- [术语/段落] → [难点类型] → [建议处理方式]
- ...
```

## 步骤 2：组装翻译提示词

主 agent 读取 `01-analysis.md`，按技能入口指定的共享提示词模板组装翻译提示词，写入以下内容：

- **目标读者**：本次确定的受众预设或自定义描述
- **目标风格**：本次确定的风格预设或自定义描述，并单独记录 §1.3 中的原文语气评估
- **内容背景**：§1.1 中的摘要
- **术语表**：合并后的术语表，含 §1.2 中提取出的术语
- **翻译难点**：§1.4 中的全部难点

保存为 `02-prompt.md`。分块场景由子 agent 使用该提示词，非分块场景由主 agent 自己使用。

## 步骤 3：初稿

保存为输出目录中的 `03-draft.md`。

分块内容由子 agent 产出该初稿（由各分块译文合并而来）。非分块内容由主 agent 直接产出。

依照 `02-prompt.md` 翻译全文。应用 SKILL.md 中的全部**翻译原则**。

## 步骤 4：批判性审校

主 agent 对照原文批判性审校初稿。把审校发现保存到 `04-critique.md`。本步骤只产出**诊断结论**——暂不重写。

### 4.1 准确性

- 逐段与原文对照
- 核实事实、数字、日期、专有名词
- 标出误加、漏译或改动的内文
- 检查术语与术语表的一致性

### 4.2 母语自然度

- 标出读起来像"译文"而非"原文"的句子——不自然语序、硬译、生硬措辞
- 面向中日韩目标语言时：检查不必要的连接词（因此／然而／此外）、滥用被动语态（被／由／受到）、名词堆叠、过度名词化
- 标出直译后不自然的比喻
- 检查情感色彩是否被保留而非被抹平
- 注明哪些地方重构句子能提升可读性

### 4.3 注释与适配

- 译注是否准确、简洁、真正有用？
- 标出遗漏的、需要加注的理解难点，以及对着显然的术语过度加注的地方
- `02-prompt.md` 中的翻译策略是否被遵循？
- 文化引用在目标语言中是否成立？

**保存 `04-critique.md`**，结构如下：
```
## 准确性
- [问题]：[位置] —— [描述]

## 母语自然度
- [问题]：[例句] → [建议改法]

## 注释与适配
- [增加/删除/修改]：[术语/段落] —— [理由]

## 小结
[总体评估：X 个关键问题，Y 处可改进]
```

## 步骤 5：修订

落实 `04-critique.md` 中的全部发现，产出修订后的译文。保存为 `05-revision.md`。

读取 `03-draft.md` 与 `04-critique.md`，修正所有准确性问题，重写不自然的表达，调整注释，改善行文流畅度。

## 步骤 6：润色

把最终版本保存为 `{source-filename}`，与源文件同名。

对 `05-revision.md` 做出版级质量的最后一轮打磨：

- 把整篇译文当作独立作品通读——读起来像母语原生内容吗？
- 抚平残留的粗糙过渡
- 确保全篇叙述声音与风格一致
- 最后一轮术语一致性检查
- 确认格式被正确保留

## 子 agent 的职责

每个子 agent（每个分块一个）必须使用全新上下文，不继承父对话；主 agent 显式传入共享提示词和源文的绝对路径、块序号与论证位置、输出路径和验收条件。子 agent **只**负责产出自己分块的初稿（步骤 3）。主 agent 负责组装共享提示词（步骤 2）、并行启动全部子 agent，然后接管批判性审校（步骤 4）、修订（步骤 5）与润色（步骤 6）。

## 分块 refined 翻译

当内容超过分块阈值且使用 refined 模式时：

1. 主 agent 先对**整篇**文档做分析（步骤 1）→ `01-analysis.md`
2. 主 agent 组装翻译提示词 → `02-prompt.md`
3. 切分为分块 → `chunks/`
4. 使用全新上下文并行启动每块一个子 agent（显式传入 `02-prompt.md`、源块和输出文件的绝对路径、位置说明与完成标准）→ 把所有结果合并为 `03-draft.md`
5. 主 agent 批判性审校合并后的初稿 → `04-critique.md`
6. 主 agent 依据审校意见修订 → `05-revision.md`
7. 主 agent 润色 → `{source-filename}`
8. 最终跨分块一致性检查：术语、叙事流、分块交界处的过渡
