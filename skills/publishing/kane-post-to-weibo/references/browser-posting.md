# 浏览器投稿

## 打开编辑器

1. 读取所选浏览器工具的用法和授权规则。用独立任务页打开 `https://weibo.com/`，核对当前登录账号。登录、安全验证或扫码交给用户，交回控制权后在同一会话重新观察账号与编辑器。遵守工具的接管和拒绝状态。
2. 普通微博从首页发布框或「写微博」进入。头条文章从发布框的「头条文章」入口进入，按页面提示选择新建或「写文章」。打开新标签页时辨认本次打开且已加载的编辑页。入口、账号权限和可用功能以当前页面为准。[微博客服的头条文章说明](https://kefu.weibo.com/faqdetail?id=20850)
3. 填写前核对编辑器为空。只有用户要求续做时才编辑已有内容，并用账号、草稿 ID 或内容特征核对目标。编辑器可能自动保存，打开或填充后若跳转或超时，先查本次编辑页和草稿记录再继续。

## 普通微博

用当前工具支持的输入方式填入纯文本，并在编辑器自带的图片或视频控件上传已核对的本地文件。每次上传后观察缩略图、视频处理进度和平台校验。按用户给定的顺序核对附件，必要时用界面重排。话题、提及和可见范围按用户指定设置，其余沿用界面默认值。媒体失败时定位具体文件，先读回现有附件再决定是否重试。

## 头条文章

1. 读取 `meta.json`，填标题、摘要及用户指定的字段；封面用编辑器的封面控件上传并检查裁剪。超限按当次页面校验处理。使用空白正文区，确认焦点后以工具支持的富文本方式粘贴 `body.html`。例如在支持富文本粘贴的 ego-browser 版本中，用工具的文件读取能力将 `body.txt`、`body.html` 分别作为 `page.keyboard.paste({ text, html })` 的值传入。工具仅能填纯文本时，保留本地富文本请用户协助，或经用户接受后使用 `body.txt` 并说明结构差异。
2. 按清单逐一定位插图标记，在该位置用编辑器的插图控件上传本地文件。确认该图片已出现在对应位置，再移除它的标记。相同图片可以出现在不同位置，每个标记独立核对。若编辑器把图片插错段、找不到标记或不支持准确定位，保留已完成部分和清单供用户继续。正文图与封面分别核对。
3. 读回开头、中段和结尾，检查原稿实际使用的标题、列表、引用、链接、表格和代码块。平台可能改变粘贴后的结构；发现缺文、错位、丢失链接或格式变化影响含义时，先修复或报告具体差异。确认所有插图上传完成，预期数量、顺序与位置相符，正文无残留标记。

## 草稿与交接

用户明确要存草稿时，使用当前编辑器的保存草稿功能或已确认的自动保存。通过目标账号下的草稿记录核对同一稿件，避免在重新打开前丢失当前编辑页。结果不明时先核对现有记录和可见 ID，再决定下一步。平台没有可核实的草稿记录时，说明页面实际状态并保留编辑器。

按浏览器工具的规则把编辑页交给用户，告知账号、已填内容和缺项。提交、发布、定时和二次确认由用户在平台完成。用户手动提交后要求核验时，按账号、时间和内容核对个人主页或文章记录。审核中单独报告，链接只使用平台提供的公开地址。
