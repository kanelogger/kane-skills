# X Articles 本地排版

输入一份 UTF-8 的 `.md` 或 `.markdown` 文件。对话中提供的成稿可原样写入新的 Markdown 文件。用技能入口确定 `${BUN_X}` 与 `{baseDir}`，完成依赖安装后运行。

```bash
${BUN_X} "{baseDir}/scripts/main.ts" "/path/to/文章.md" --cover "/path/to/封面.png"
```

- 标题依次取 `--title`、YAML `title`、正文开头的 H1 或文件名。开头的 H1 与标题相同且没有图片或链接时，正文只保留其余部分。
- 封面优先用 `--cover`，其次用 YAML `cover_image`（兼容 `cover` 和 `image`）。没有指定时正文图片保持原位。
- 正文及 YAML 内的本地图片用相对于稿件实际目录的路径。图片可放在子目录，软链接目标也须在稿件目录内。显式封面接受绝对路径或相对于调用目录的路径。支持本地 PNG、JPEG、GIF 和 WebP，实际上传以 X 的校验为准。
- Markdown 正文保留标题、链接、加粗、斜体、引用、列表、代码和表格的 HTML 表达。原始 HTML 当作文字。相对链接和非 HTTP(S) 链接转成链接文字。X 编辑器可能调整格式，尤其是表格和代码，需要在平台预览中核对。

默认在稿件同级的新 `<稿件名>-x/` 目录输出文件。用 `--output-dir` 另选目录，已有目录会报错。成功时 stdout 为 JSON，错误写入 stderr 且退出码非零。

| 文件 | 核对内容 |
| --- | --- |
| `body.html` | 可直接打开的正文预览和富文本粘贴内容，图片以可见标记显示 |
| `body.txt` | 纯文本备选，包含链接地址和同一组图片标记 |
| `meta.json` | 标题、封面、按正文顺序排列的图片、产物路径和警告。每个正文图片有 `marker`、`source`、`alt` 及本地 `file` |

`file: null` 表示该图片只有 HTTPS 来源。请为清单中的每一项配对用户认可的本地副本再进行完整草稿或发表交接。完成本地准备时确认正文首尾完整，清单中每个标记在预览里有一个对应位置，并报告任何未配对图片。
