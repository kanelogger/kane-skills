# 浏览器投稿

## 会话和账号

1. 先读取所选浏览器工具的当前文档和授权规则。在独立任务页操作，沿用用户已有的登录态。遇到登录或验证码时交给用户，交回控制权后重新观察页面并核对 `@账号`。
2. 新建前确认未进入其他稿件。只有用户指定继续编辑时才打开现有草稿，按账号、标题或正文及可见 ID 核对目标。编辑器加载慢时先确认是否已打开，避免重复新建。
3. 用户指定的工具无法完成时，说明缺少的能力并请用户接管当前步骤或指定其他工具。已填入内容或上传过媒体时，先查看同一任务页和草稿列表，确认进度后再转交。

## 填写普通帖和引用帖

1. 普通帖打开 [帖子编辑器](https://x.com/compose/post)。引用帖打开目标 X 的 HTTPS 帖子链接，在目标帖的转发菜单中只选 `Quote`，核对编辑器显示的引用卡片。直接转发会对外生效。
2. 通过编辑器输入文本，通过可见媒体按钮和所选工具支持的文件选择器上传本地附件。等待每项上传或处理完成，核对媒体数量、顺序、缩略图，以及正文和引用卡片。字数和媒体限制按当前账号的编辑器校验。

## 填写 X Articles

1. 先为封面和正文图片准备清单对应的本地文件，缺项时交付预览并说明所缺素材。素材齐全后，在 [X Articles 编辑器](https://x.com/compose/articles) 中新建文章，或从 X 侧栏 Articles 入口进入。功能是否可用取决于当前账号的权限。填入本地 `meta.json` 的标题，按清单单独上传封面。
2. 将 `body.html` 和 `body.txt` 分别作为富文本和纯文本备选。ego-browser 在支持的平台可用文档中的 `page.keyboard.paste({ text, html })`。先定位可见的正文编辑区并确认焦点，用工具支持的文件读取方式传值。工具缺少富文本输入时，交用户粘贴或经用户同意后用纯文本。
3. 按 `images` 顺序定位每个 `marker`。在编辑器的 `Insert → Media` 中通过可见的 `Add photos or video` 控件选择对应本地文件。等待图片在正确位置出现，再精确删除仍可见的标记。标记在段落中间且编辑器只能插入独立图片块时，核对拆段后的文字和图片顺序。无法可靠定位、上传或删除标记时停在当前稿件并交接。
4. 使用当前界面提供的预览，核对标题、封面、正文的开头、中段和结尾、链接、样式以及实际图片数量和顺序。检查清单中的每个标记均已清除。缺图、正文被截断或排版降级影响含义时，先补齐或取得用户对调整的意见。

## 保存、交接和读回

| 目标 | 操作及证据 |
| --- | --- |
| 保存草稿 | 使用编辑器可见的保存选项或确认自动保存。在草稿列表或重新打开的同一稿件中读回标题、正文特征和媒体。当前账号或帖子类型不提供可核实的保存方式时，保留任务页并报告「编辑器已填充」。 |
| 发表 | 交接前汇报 `@账号`、正文或文章标题、附件、引用目标与可见受众。保留当前编辑器，由用户点击 `Post` 或 `Publish` 并完成平台提示。交回控制后，从成功提示、详情页或账号发表记录取得实际链接，核对对应内容。 |

线上状态不明时，优先在同一账号按正文特征、标题、操作时间或可见 ID 核对。未确认结果前保留当前任务页，避免再次新建或提交。需要用户继续时按浏览器工具规则交接。核验结束后归还借用页，或关闭本次创建且无未保存内容的任务页。
