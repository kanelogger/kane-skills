# 成稿清晰改写

改写已有文档的表达，让目标读者无需知道写作过程也能理解其结论、依据和限制。保留文档原本的用途、事实、立场、语气和必要的专业精度。

## 输入与边界

1. 读取完整成稿。用户指定术语表、需求文档、规格说明或其他依据时，也读取与本稿相关的部分。区分这些资料中已定义的术语、原稿中的临时叫法，以及引用文本。
2. 从文档用途和用户要求确定读者。读者未知时，按“了解该领域，但未参与本次工作”处理。只补读者理解当前内容必需的背景。沿用原稿语言，除非用户指定输出语言。
3. 背景只能来自原稿、用户给出的资料或本次已核验的来源。缺少依据时保留缺口或提出待确认项，不把推测写成事实。
4. 这是表达改写。不要借机新增主张、修正事实、改变结论力度，或抹去例外、时间范围、适用条件和不确定性。发现疑似事实错误时单独指出，不静默修正。

## 改写方法

- 用具体的对象、动作、条件和结果解释抽象说法。删去没有定义、没有必要且不能帮助读者判断的合成词；如果一个概念确实需要专名，先说明其含义，再稳定使用同一名称。
- 沿用用户指定资料中已有的领域术语及其定义，不因术语陌生就改名。术语首次出现时，仅补目标读者需要的简短解释。资料之间定义冲突时指出冲突，不自行统一。
- 让每句话明确“谁或什么，在什么条件下，做什么，产生什么结果”。拆开过长的句子，减少多层嵌套和指代不明；保留必要的逻辑连接。
- 背景放在读者首次需要它的位置。用简短的具体例子帮助理解复杂关系，但不要用例子替代规则，也不要编造真实案例。
- 保留原文的文类和结构意图：技术说明仍说明行为与边界，决策报告仍交代判断与依据，文章仍保留论证与作者声音。仅在原结构妨碍理解时调整段落或顺序。
- 借鉴 ASD-STE100 的清晰、简洁、无歧义原则。中文改写不宣称符合该英文标准的词汇或语法规则，也不机械套用句长限制。英文改写若被要求严格符合 ASD-STE100，应核对正式规则和词表；未核对时不声称合规。

## 受保护内容

原样保留直接引文、代码、命令、配置、路径、标识符、数字、单位、公式、链接、引用标记、官方名称和有固定含义的字段名。可以改写它们周围的说明；需要改动受保护内容时，先说明原因并取得用户的明确要求。

## 交付

- 粘贴的文本：直接给出改写稿。改动较大时，附一小段说明，列出补入的背景、被替换的临时叫法和仍待确认的术语；不要让说明盖过正文。
- 文件输入：默认保留原件，在同目录生成名称带 `-clarified` 的副本；目标文件已存在时选用未占用的编号。用户明确要求原地修改时才覆盖。尽量保持原文件格式和有效结构；无法可靠编辑该格式时，说明限制并交付可编辑的文本副本。
- 交付前对照原稿和术语资料，确认事实、数字、限制条件、引用及专业术语没有被改写出新的含义。对无法确认的地方明确标注，不声称已解决。
