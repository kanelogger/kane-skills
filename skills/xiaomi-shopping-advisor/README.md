# xiaomi-shopping-advisor

> 我买东西不一定会买小米，但是一定会参考小米的商品。比小米贵的，一定是用料或者是功能比小米好的我才会选；同理，比小米便宜的，潜意识就会看一看有没有减配或者是不足。
> 这里还有一个小技巧，之前也说过：传统行业，小米的东西都可以买，至少不亏，比如插线板、水杯、毛巾；如果有互联网大厂跟着卷，小米的优势可能就没那么大了，比如安克、徕芬、石头、极米之类的。逻辑很简单：互联网大厂在小米这个规模下还能整活的，那这个产品要么更好，要么性价比确实更高。


以可比的小米具体型号作为价格和能力锚点，分析便宜款减配了什么、贵款的提升是否值得。默认直接给出精简建议；用户明确要求时再生成带产品图和响应式对比表的独立 HTML 报告。

## 适合处理

- “这个品类买哪款？”
- “比小米便宜的型号减配在哪里？”
- “多花钱买安克、徕芬、石头、极米等品牌是否值得？”
- “帮我做一份带图片、价格、参数和来源的商品横评网页。”

## 核心原则

- 小米是比较锚点，不是默认答案。
- 只比较当前在售的精确 SKU，不混用系列、容量和代际。
- 价格、关键参数、认证和结论要能追溯到来源。
- 品牌经验只负责发现候选，不能替代产品证据。
- 安全、兼容和硬性需求先门禁，再讨论综合性价比。
- 先轻量扫描、再深研默认 3 个决赛候选，避免对淘汰型号做无效调研。
- 图片只在图文报告中尝试获取，默认不影响推荐；用户明确要求每款必须带图时才作为交付门禁。

## 输出

默认在对话中给出默认推荐、预算选择、升级条件、不推荐条件和直接来源。

用户要求 HTML、网页、带图或完整报告时输出：

```text
shopping-report-<category>-YYYY-MM-DD/
├── index.html
└── assets/products/
    └── <brand>-<model>.webp
```

HTML 包含首屏结论、产品卡片、锚点式对比表、减配与溢价审计、场景化建议、调研日期和证据来源。无法取得可验证的精确型号图片时，卡片显示明确缺图状态。

## 使用示例

- `Use $xiaomi-shopping-advisor to 推荐 500 元以内的吹风机。`
- `Use $xiaomi-shopping-advisor to 推荐 500 元以内的吹风机，输出带产品图的 HTML 对比报告。`
- `用 $xiaomi-shopping-advisor 比较小米、安克和其他 100W 充电器，重点检查安全与协议兼容。`
- `用 $xiaomi-shopping-advisor 分析扫地机器人，比小米更贵的型号究竟升级了什么？`

## 评测

`evals/` 使用文章中的两个真实产品执行端到端测试：小米巨能写与小米彩虹电池。用例要求核验当前市场、聚焦 3 个决赛候选、生成 HTML 横评，并通过结构和商品特定规则校验。图片为尽力获取项，不再阻塞默认评测。

```bash
skill-up validate evals/eval.yaml
skill-up run evals/eval.yaml
```
