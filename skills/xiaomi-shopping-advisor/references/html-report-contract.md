# HTML 报告契约

只在用户要求 HTML、网页、带图或完整报告时读取本文件。HTML 是该模式的主交付物，不是 Markdown 报告的包装。

## 1. 目录与命名

用户未指定路径时，在当前工作目录创建：

```text
shopping-report-<category>-YYYY-MM-DD/
├── index.html
└── assets/products/
    ├── <brand>-<model>.webp
    └── ...
```

目录和文件名使用简短 ASCII slug。不要覆盖现有报告；重名时添加短后缀。复制 `assets/report-template.html` 为 `index.html`，替换全部 `{{...}}` 占位符并删除不适用的示例块。

## 2. 必备页面区块

| id | 内容 |
| --- | --- |
| `summary` | 一句话判断、默认/预算/升级建议、市场和调研日期 |
| `products` | 每个进入对比的精确 SKU 卡片；已验证图片或明确缺图状态 |
| `comparison` | 锚点居中的核心对比表 |
| `price-audit` | 便宜款减配和贵款溢价解释 |
| `scenarios` | 按人群或场景给出选择与不推荐条件 |
| `evidence` | 来源、证据标签、价格条件和待核实项 |

首屏必须直接回答“买哪个、为什么、谁应该升级”。

## 3. 产品图片

图片只在决赛候选确定后处理。每款最多尝试两个已核验来源，优先从产品页的 JSON-LD `Product.image` 或 `og:image` 取得，不要先进行宽泛图片搜索。

已取得的图片必须：

1. 优先品牌官网、官方说明书媒体或官方旗舰店主图。
2. 打开原始页面核对型号；搜索结果缩略图不算核对。
3. 下载到 `assets/products/`，HTML 使用相对路径；不得依赖远程热链、Data URI 或运行时脚本。
4. 使用能合理保留细节的 WebP、PNG、JPEG 或 AVIF；使用浅色统一画布和 `object-fit: contain`，不裁掉产品主体。
5. `alt` 包含品牌和完整型号；图片外层链接指向原始产品或图片来源页。
6. 不得用生成图、相邻型号、概念图或包装盒图冒充实物主图。

下载后先核验文件签名和浏览器可解码性，不要只相信扩展名或响应头。若检视工具不能读取 AVIF，只再尝试从同一已核验来源取得 PNG、JPEG 或 WebP 版本。保留图片来源 URL，并在浏览器检查中确认已引用的本地图实际加载。

两次尝试仍无法取得可验证图片时，保留该候选并在 `.product-card` 中使用“未取得可验证的精确型号图片”纯文字状态；不使用空 `img`、近似产品图或相邻型号图。图片获取失败不得改变推荐。

只有用户明确要求“每款都必须带本地真图”时，才启用严格图片门禁。该模式下图片缺失应报告为未完成，仍不得为了凑齐图片更换购买结论。

## 4. 产品卡片

每张 `.product-card` 至少包含推荐角色、完整型号和版本、价格条件、适用人群、关键优势、主要不足、证据状态和直接产品来源。不要堆积不会改变购买决定的官方卖点。

## 5. 对比表

使用 `<table class="comparison-table">`，把有效锚点放在中间列或标明“基准”。行至少覆盖价格与差价、核心材料或性能、安全或兼容、耗材配件、保修维护、升级、减配和推荐人群。

使用文本和图标共同表达 `提升`、`持平`、`取舍`、`减配`、`待核实`，不只靠颜色。手机端用 `.table-scroll` 横向滚动并显示提示，不把表格缩成小字。

## 6. 差价解释

`price-audit` 必须同时出现：

- **少花的钱牺牲了什么**：具体减配、证据、场景影响；
- **多花的钱买到了什么**：绝对差价、比例、可验证收益、适合谁。

无法证明的升级写成 `待核实`，不能用“旗舰体验”“全面升级”代替证据。

## 7. 来源和时效

- 使用 `<time datetime="YYYY-MM-DD">` 标注调研日期。
- 每个价格说明渠道、套装、地区和公开优惠条件；不追逐登录价、定向券或不可复现的结算价。
- 来源直接链接正文页，不链接搜索结果页；区分官方规格、独立实测、用户反馈和合理推断。
- 每款默认最多使用一个官方规格页、一个价格页和一个必要的独立证据。图片、价格、规格来自不同页面时分别说明。
- 购买链接不得带未披露的联盟或跟踪参数。

## 8. HTML 与视觉

- 单个语义化 HTML5 文件，CSS 内嵌；不依赖外部 CSS、字体、JavaScript、框架或 CDN。
- 使用系统字体；正文最小 16px，触控目标不小于约 44px。
- 键盘焦点可见、对比度足够、图片有 `alt`、链接文字可理解。
- 页面最大内容宽度约 1180–1280px；卡片响应式排列。
- 状态色仅作辅助：绿色为有证据的提升，黄色为取舍，红色为风险或减配，灰色为未知。
- 可加入价格定位条或相对差异条；不要使用会制造虚假精度的雷达图。
- 不加入自动播放、弹窗、倒计时、虚假购买按钮或追踪代码。

## 9. 验证

从 Skill 根目录运行：

```bash
python3 scripts/validate_report.py /absolute/path/to/shopping-report-category-YYYY-MM-DD
```

严格带图模式改用：

```bash
python3 scripts/validate_report.py /absolute/path/to/report --require-images
```

校验通过后，实际打开桌面宽度约 `1440 × 900` 和手机宽度约 `390 × 844`，检查首屏结论、已引用图片、缺图状态、卡片溢出、表格滚动、来源链接、控制台错误和模板占位符。脚本通过不能替代视觉检查。
