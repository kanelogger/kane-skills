# 商品分析框架

本文件控制候选选择、证据判断和购买结论。分析时完整读取。

## 1. 购买任务卡

先建立一张内部任务卡，不必把所有问题都抛给用户：

| 字段 | 要回答的问题 |
| --- | --- |
| 市场 | 国家/地区、币种、可接受渠道 |
| 场景 | 在哪里、给谁、以什么频率使用 |
| 预算 | 理想价、硬上限、是否接受长期耗材 |
| 必需项 | 缺少就不能买的功能、尺寸、协议或认证 |
| 排除项 | 噪音、重量、生态绑定、安装、隐私等不可接受项 |
| 生命周期 | 预计使用年限、维修和保值是否重要 |
| 偏好 | 外观、品牌、生态等软偏好 |

只有缺失字段会改变候选池或安全结论时才追问。否则采用合理假设，并在报告首屏的“分析口径”中列明。

## 2. 品类风险

| 风险 | 典型品类 | 必须加重的证据 |
| --- | --- | --- |
| 低 | 毛巾、普通杯具、收纳、无源配件 | 材料、尺寸、工艺、价格、退换 |
| 中 | 吸尘器、投影仪、吹风机、扫地机器人 | 性能实测、耐久、耗材、维修、软件支持 |
| 高 | 插线板、充电器、电池、取暖器、净水、婴童和健康相关用品 | 法规认证、安全设计、召回、专业测试、失效后果 |

风险取决于失效后果，不取决于售价。高风险产品任何关键安全项证据不足时，不得成为默认推荐。

## 3. 候选漏斗

先轻量扫描最多 6 个候选，只记录完整型号、公开价、角色和一个直接页面。然后筛选为默认 3 个决赛候选：小米锚点、最有意义的省钱款、有可验证收益的升级款。只有三款无法覆盖用户场景或结论仍无法区分时，才增加第 4 款。

只对决赛候选做深度核验、图片获取和报告制作。被淘汰的候选不再搜集说明书、评测、用户反馈或图片。

候选角色：

1. 小米基准款：同用途、同代际、价格段相邻的具体型号。
2. 预算款：价格显著更低，但仍满足硬性需求。
3. 同价竞争款：验证小米是否真有优势。
4. 升级款：价格更高，声称用料、性能或体验更好。
5. 品类专业款：来自长期聚焦该领域的传统或垂直品牌。
6. 互联网挑战者：以工程、软件、供应链或新功能进入品类的品牌。

不要因为销量高就纳入，也不要因为品牌知名就排除。排除理由应是型号不可比、证据不足、已停产、渠道异常、硬性需求不满足或存在红线。图片难获取不是排除商品的理由。

## 4. 小米锚点有效性

逐项检查：

- 用途与用户场景相同；
- 当前在售，且不是清仓造成的异常价格；
- 同代际、同容量或可合理归一化；
- 不依赖用户没有的生态条件；
- 价格位于候选集可比较范围；
- 区分小米自营、米家品牌、生态链品牌和仅在小米有品销售。

任一核心条件不成立时，小米只能作为旁观候选，不能作为价值锚点。改用“市场主流款 + 品类专业款”双锚点，并在报告解释原因。

## 5. 最小证据台账

为每个决赛 SKU 必须记录：

- 品牌、完整型号、代际和容量/尺寸/套装；
- 调研日可购买状态、公开价、价格条件和渠道；
- 3–5 个会改变购买决定的规格或性能差异；
- 安全、兼容和用户硬性需求；
- 主要不足、保修和未确认项；
- 支持上述信息的直接页面。

只在会改变决策时补充说明书、认证、耗材、安装、独立测试、长期使用、维修证据或重复缺陷。图片只在图文报告模式中记录。

每款默认最多 3 个正文来源：官方规格或说明页、当前价格页，以及结论需要时的一个独立证据。同一页已能支持多项时不再重复搜索。

证据标签：

- `已验证`：一手资料或可重复实测直接支持。
- `厂商宣称`：仅由品牌或商家提出。
- `用户反馈`：多个真实使用反馈重复出现，仍可能有样本偏差。
- `合理推断`：由事实推导，来源没有直接下结论。
- `待核实`：当前没有足够证据。

同一厂商稿件被多个站点转载不算独立来源。带货评测、联盟链接和厂商送测要降低独立性权重。

## 6. 统一比较口径

比较前优先统一：

- 容量、尺寸、额定参数、套装和版本；
- 含税、运费、优惠券、会员、定金和以旧换新条件；
- 会影响决策的必需附件、安装、网关、订阅和耗材；
- 对该品类或用户重要的保修、维修可得性和软件支持；
- 使用场景下的持续性能，而非只看峰值参数。

必要时计算：

`预期总成本 = 到手价 + 必需附件 + 安装 + 预期耗材 + 订阅 + 合理可估的维修/替换成本`

只在长期成本可能改变推荐时计算。无法可靠估算的项目单列，不制造精确数字。

## 7. 双向差异审计

### 比锚点便宜

依次检查材料与工艺、核心部件、安全保护、持续性能、附件与协议、品控与售后。每项减配必须回答“对目标场景有没有实际影响”。用户用不到的功能被删除，可以构成合理省钱。

### 比锚点昂贵

每项溢价必须回答：多花多少钱和多少比例；得到什么改善；由什么证据支持；用户是否会感知；是否降低长期成本或风险。外观、品牌故事、功能数量和峰值参数不能自动证明溢价合理。

### 互联网挑战者

“能在小米规模旁竞争”只提高进入候选池的优先级。继续验证核心技术、持续迭代、长期可靠性、售后、软件依赖和场景价值。

## 8. 决策顺序

先门禁，后排序：安全和合规；兼容性与硬性需求；证据充分性；场景适配；总成本与差价价值。

需要评分时按用户需求调整权重。缺少明确偏好时可从以下起点开始：

| 维度 | 默认权重 |
| --- | ---: |
| 场景适配 | 30% |
| 核心性能 | 20% |
| 可靠性与安全 | 15% |
| 长期总成本 | 15% |
| 售后与维护 | 10% |
| 当前价格 | 10% |

分数用于整理判断，不得伪装成实验精度，也不得让高总分抵消门禁失败。报告必须同时给出原始事实与评分依据。

## 9. 推荐结论

最终覆盖默认推荐、预算选择、值得升级、不推荐条件；候选均触发红线或证据不足时写“暂无合格产品”。采用“结论 + 差异 + 条件”表达：

> 默认选 A。B 便宜约 25%，主要少了低频联网功能，适合纯手动使用；C 贵约 40%，只有每天高频使用且重视噪音时才值得升级。

不要写“闭眼买”“全网最佳”“绝对安全”或没有范围的“性价比最高”。
