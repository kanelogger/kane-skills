# subtext-article

把字幕、ASR 转写、播客或访谈逐字稿整理成忠实原文的中文文章，保留源文副本与可读转写供回查，不强制归档每一步。

## 适用场景与边界

- 输入已有转写文件或粘贴文本，如 B 站 AIsubtitle、Whisper、YouTube json3、SRT/VTT、ASS/SSA、LRC、timedtext XML/TTML 或纯文本。
- 目标是可独立阅读的文章，不是摘要：保留重要主张、论证顺序、数据及单位、例子、引文和限定条件。
- 不负责下载视频、生成 ASR、翻译或补充背景研究。含混的人名、数字和说法不会靠猜测补全；影响保真的缺口需要补料。

## 输出

提供文件或粘贴文本即可；可附输出位置、体例和篇幅要求。默认简体中文，使用 `Title:`、`Overview:` 和 `##` 正文分节，正文为连续段落。篇幅以信息完整为准，不强制压到原长的 70%–90%。

在源文件旁新建 `<source-stem>_article/`，源文副本、可读转写和终稿放在一起，原文件保持不动。终稿使用源文件名去掉最后一个扩展名后加 `.md`，例如 `访谈.zh.srt` → `访谈.zh_article/访谈.zh.md`。粘贴文本先保存为唯一命名的 `.txt` 源文件，再走同一流程：

```text
<source-stem>_article/
  00-source.<ext>
  01-normalized.txt
  <source-stem>.md
```

仅当源文副本与终稿重名（不区分大小写）时，给副本加 `work-` 前缀，终稿名称不变。

## 工作方式

1. 复制原件，提取可读转写，核对提取结果并通读全文。
2. 梳理观点、依据和口语关系；短稿在工作上下文中完成，长稿跨多次读取或写作、需要防止遗漏时保留带源文定位的必要笔记。
3. 组织成文，再做“源文是否遗漏”和“文章是否新增”的双向核对，确认书面化没有改变含义。
4. 保存同名 Markdown 终稿，报告目录、终稿路径及必要限制；不额外归档固定初稿、自检报告或状态清单。

去掉无信息的口头填充、重复和推广互动，不删除其中承载的实质内容；保留影响含义的说话人归属、分歧、否定和不确定性。引语需改写时转为间接转述，不把润色过的文字当原话。

只有指向唯一时才把口语指代换成明确名称；问题中的假设不自动视为受访者的结论。合并重复时保留新增条件、证据和强调，区分口误订正与立场变化。阅读分块不直接充当章节；分块写作共享全文梳理结果，合并后统一核对跨块关系，不把缺乏共享依据的局部稿直接拼接交付。

## 单独使用脚本

脚本依赖 Python 3.9+ 标准库，没有第三方依赖。以下路径中的 `<skill-dir>` 指复制或安装后的本技能目录：

```text
python3 "<skill-dir>/scripts/prepare_article_package.py" "<source-file>"
python3 "<skill-dir>/scripts/prepare_article_package.py" "<source-file>" --output-dir "<new-package-dir>"
python3 "<skill-dir>/scripts/normalize_subtitle.py" "<source-file>" --output "<normalized.txt>"
```

打包脚本只生成源文副本与 `01-normalized.txt`，成功只表示材料已准备好，不代表文章完成。非空目录拒绝覆盖，需另选目录。归一化失败时退出非零，保留已复制原件并报告错误；空正文或无法识别的结构化输入不会被当作可写文章。

写作、保真和中文排版规则均在本技能内，无须调用其他技能或读取仓库文件；复制整个目录即可独立使用。
