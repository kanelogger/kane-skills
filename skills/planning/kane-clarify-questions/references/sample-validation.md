# 最小样例验证

当用户需要看过内容或体验交互才能判断时使用。普通的事实缺失仍通过查阅材料或询问解决，不把每个「不知道」都转成做原型。

## 选择能帮助判断的最小样例

1. 明确本次要验证的一个决定及其前置条件；前置条件未明确时，先解决前置问题，不围绕猜测制作样例。
2. 优先复用用户已有样例。在现有授权范围内，可以直接在对话中给出简短样例，例如同一事实内容的两种文章开头、同一任务的两种步骤安排；各版本仅改变待比较的因素。
3. 样例只做到足以支持该决定，不扩展成完整稿件、产品实现或另一套工作流。用户已授权的原型工作可直接衔接；若验证需要另行制作界面、采集数据或实测，且不在当前授权内，本次只写明最小验证动作、比较标准和受阻步骤，不把上下文补全变成新增制作任务。

## 用样例提问并收束

- 先展示或明确引用样例，再用具体、中立的问句询问当前决定，例如「读书会邀请信更适合采用哪段开头的语气？」。沿用入口的 User Input Tools、措辞和发出前检查规则；短问句不承载整段样例。
- 样例选择题与其他独立问题合并到本轮，共用入口规定的题数和轮次；不额外开设样例反馈轮。用户明确要求续问时，也按入口的追加规则处理。
- 用户明确选择后，将选择写入已确认事实，重新核对依赖该选择的问题；样例里的演示设定不会自动成为事实。
- 用户看过样例仍无法决定，或当前获准轮次已用尽时，保留为未确定事项，附最小验证动作及判断标准，不自行加轮。用户明确委托代定时记为假设；要求停止提问时直接收束。
