# github-reuse-scout

收到开发需求时，先在 GitHub 上搜索可复用的开源项目并判断其架构能否直接复用；能复用就基于现有方案启动开发，并在后续会话中按计划把借用代码渐进迁移到更熟悉的框架。

在 Codex 中输入 `$github-reuse-scout` 显式调用。

## Use when

- 提出新的开发需求（工具/应用/系统/服务），希望先找开源现成方案。
- 想避免重复造轮子，优先站在已有项目上开发。
- 需要在动手前得到有证据支撑的复用决策（fork / reference / none）。
- 希望基于开源项目启动后，逐步把代码迁移到自己更熟悉的框架。

## Output

- `.reuse/reuse-plan.md`：复用决策（fork / reference / none）、候选与证据、借用单元清单、迁移状态与日志。
- `.reuse/` 工作数据：搜索缓存、评分结果、逐仓库架构证据；这些文件加入 `.gitignore`，计划文件保留在版本控制内。

## 输入、依赖与安全边界

提供开发需求、目标项目目录和已知技术约束；目标框架、许可证或部署约束不确定时按当前运行时提问。脚本依赖 Python 3.9+、`curl` 和 `git`；可选用 `gh` 的已有登录凭据或环境变量令牌。搜索统一通过受限的 HTTPS JSON 下载，30 秒超时、最多 5 次重定向；克隆只接受 HTTPS GitHub 地址。

深入检查使用筛选后的显式仓库名单，不重新取原始评分前三名。启动复用只在新目录进行，保留上游历史、许可证和来源，不删除现有 `.git`；先审阅安装与测试脚本再执行。工具不可用时记录手工证据及限制。
