# kane-task-planner · 任务执行规划

开工前先确定大致方向：把任务划成主要环节，建议各环节直接完成、使用脚本、交给子代理，或复用已有 Skill。现有技能不足且有复用价值时，可以建议生成新 Skill，但不会实际创建。

## 使用

将包含 [SKILL.md](SKILL.md) 的整个目录复制或安装到支持 Agent Skills 的运行时。无需脚本或额外依赖。

仅由用户明确点名调用，普通任务不自动触发。在 Codex 中输入 `$kane-task-planner`，再说明要规划的任务。

提供任务目标、期望产出及已知约束即可；也可以附上任务材料和可用技能清单。技能会利用已有上下文，仅在信息缺失会改变执行方向时提问。

```text
使用 $kane-task-planner，为把一批访谈整理成专题报告做执行前规划。
优先复用当前可用技能，说明哪些环节适合脚本或子代理，只给大致计划。
```

## 产物

默认在对话中交付一句话目标，以及「环节 → 建议执行方式 → 理由 → 预期产出」简表，补充必要的先后关系、并行机会和待确认项。简单任务可以只用一句话；指定保存位置时仅保存计划文件。

优先选择已确认可用且匹配的技能；能力无法核实时会标为待确认。执行方式可以组合，无需每种都使用。

## 边界

只做执行前的粗粒度规划，可以只读查看必要资料和能力说明。交付计划即结束，不编写或运行任务脚本、不派发子代理、不执行推荐技能的流程，也不创建或安装 Skill。新 Skill 仅建议用途、现有缺口和复用理由。

命令、代码、详细子代理提示词和运行中的动态调整留给执行阶段。
