# Kane Prompts

`prompts/` 是提示词内容与检索元数据的唯一事实来源。

## 核心不变量

在返回、适配、组合或执行任一库内提示词前，必须在当前任务中：

1. 查看 `prompts/` 的当前文件，而不是依赖记忆、README 或固定清单。
2. 读取最终选中的每个 Markdown 文件全文；文件名和 frontmatter 只能用于初筛。
3. 以 frontmatter 做检索，以移除 frontmatter 后的正文做交付和适配底稿。

不得根据文件名、旧对话或本文件重构提示词原文。不得把临时生成的提示词冒充为库内已有内容。

## 判断用户要什么

按用户措辞选择模式；没有明确说明时，默认返回提示词正文，不直接执行：

- **查找**：用户只问是否存在、有哪些或要文件名时，仅返回匹配结果和简短差异。
- **调用**：读取对应原文，返回可直接使用的正文。
- **改写 / 适配**：从原文出发，只修改当前场景要求的部分。
- **组合**：读取所有选中原文，合成一个无冲突、可直接使用的提示词。
- **直接执行**：用户明确要求“直接执行”“用它生成结果”时，用所选正文完成任务，不回显模板。
- **维护**：用户明确要求新增或更新库内容时，修改 `prompts/` 中的文件。

“调用提示词”默认表示取出提示词，不等于执行提示词。只有用户明确要求执行时才产出最终任务结果。

## 检索流程

1. 每次都从 `prompts/` 的实时文件集合开始，不在 `SKILL.md` 维护提示词名单。
2. 按以下优先级匹配：
   1. 文件名或 frontmatter `name` 的精确匹配；
   2. `triggers` 中的常见说法；
   3. `description` 所描述的任务目标、受众和输出形式。
3. 完整读取所有最终候选，再判断其正文是否真的满足目标。
4. 优先一个精确匹配；只有多个提示词分别提供不可缺少的能力时才组合，并使用最小集合。
5. 仍有多个候选且差异会实质改变结果时，最多列出三个文件及一行差异，让用户选择；否则直接选择。

如果没有匹配：

- 用户只要求查找已有提示词时，明确说“未找到匹配的库内提示词”，不要新建、伪造文件名或暗示已经收录。
- 用户允许使用近似方案时，可以从最接近的原文轻量适配，但必须说明来源和主要差异。
- 只有用户明确要求加入提示词库时，才创建新文件；从零写一个普通新提示词不属于本技能的默认职责。

## 轻量适配边界

允许修改：

- 用用户已经提供的值替换对应变量；
- 用户明确要求的受众、语言、语气、输入范围、输出格式和约束；
- 为解决上述改动造成的直接冲突而必须调整的句子。

必须保留：

- 原提示词的任务目的、关键步骤、核心约束、成功标准和输出契约；
- 与当前场景兼容的原有结构和措辞；
- 用户未提供值的占位符，不得猜测补全。

不得做通用“润色”、整体重写、擅自增加角色或方法论、扩展任务范围，或加入当前环境无法取得的证据。用户要求“原文”“不要改”时，逐字返回正文；即使提供了场景值也不要替换。若所需改动会改变原提示词的核心结果，不要伪装成轻量适配；明确说明它需要新提示词，并仅在用户要求时创建。

除非用户要求翻译，或目标语言是明确场景约束，否则保持原文语言。

## 组合规则

1. 先分别完整读取每个来源。
2. 只保留各来源对当前任务不可缺少的能力，删除重复说明。
3. 合并角色、输入、步骤和成功标准；最终只能有一个一致的输出契约。
4. 冲突时依次遵循：用户当前指令、与目标更直接相关的来源、较窄且更可验证的约束。
5. 不得以“组合”为由引入未选来源中的新框架或要求。

## 交付格式

- 默认先用一行标明来源，例如 `来源：prompts/概念寓言.md`；组合时列出全部来源。
- 用户要求“只返回提示词”时省略来源说明和其他解释，只输出提示词正文。
- 除非用户要求完整 Markdown 或元数据，否则不输出 YAML frontmatter。
- 正文保持可复制；不要把选择理由、内部分析或适配说明插入提示词内部。
- 未解析变量保留原占位符并保持醒目。
- 直接执行时遵循所选提示词的输出契约，只返回任务产物。

## 提示词文件契约

`prompts/` 中每个可复用提示词必须：

1. 以 YAML frontmatter 开头，并包含 `name`、`description`、`triggers` 和 `inputs`。
2. 在 `triggers` 中记录用户真实会说的典型短语；检索信息不另建索引。
3. 只承载一个稳定意图；无关结果拆成不同文件。
4. 仅对跨场景变化的值使用明确的 `{{VARIABLE}}` 占位符，并在 `inputs` 中说明必填、可选和默认值。
5. 明确任务、必要约束、成功标准和输出契约；需要用户材料时，把材料与指令分隔。
6. 移除 frontmatter 后仍可直接使用。

新增场景只需添加语义明确的 Markdown 文件；不要把文件名同步进 `SKILL.md` 或维护第二份目录。仅在具体提示词确有需要时增加 `scripts/`、`references/` 或 `assets/`。

## 交付前检查

- 已在当前任务中读取正确原文全文。
- 选择与用户目标、受众和输出形式一致。
- 改动只覆盖用户场景需要，未意外重写原提示词。
- 已知变量处理正确，未知变量未被臆测。
- 组合后的角色、约束和输出契约没有冲突或重复。
- 没有把未收录内容表述为库内提示词。
- 最终内容无需二次清理即可复制或执行。
