# Kane Prompts

一个以 `prompts/` Markdown 原文为中心的常用提示词库。技能负责查找、调用、轻量适配、组合和按需执行；新增场景只需增加提示词文件。

`SKILL.md` 是机器执行规则的唯一来源。本文件只说明维护方式，不复制提示词目录或路由规则。

## 核心行为

1. 每次从 `prompts/` 的实时文件集合检索，不依赖记忆或固定清单。
2. 先完整读取选中的 Markdown 原文，再按用户场景做最小改动。
3. 默认返回提示词正文；只有用户明确要求时才直接执行。
4. 查无匹配时明确说明，不把临时生成内容冒充为已收录提示词。

## 支持的请求

- 按名称调用已收录提示词。
- 按目标、受众或输出形式查找最匹配的提示词。
- 替换变量，或轻量调整受众、语言、语气、输入范围、格式和约束。
- 组合多个互补提示词，统一角色、步骤和输出契约。
- 按用户明确要求直接执行所选提示词。
- 新增或更新可复用提示词。

从零编写或深度优化一个与本库无关的新提示词，应使用专门的提示词优化能力，不由本技能接管。

## 调用示例

```text
用 $kane-prompts 调用“三段式概念寓言”，领域是分布式系统。

用 $kane-prompts 找一个适合向零基础读者解释 RAG 的大图少字提示词，不要执行。

用 $kane-prompts 把“方法沉淀”轻量适配为只分析当前 Git 仓库。

用 $kane-prompts 组合“概念寓言”和“Visual Beginner Tech Explainer”，返回一个提示词。
```

## 目录结构

```text
kane-prompts/
├── SKILL.md              # 触发、检索、适配、组合和维护规则
├── README.md             # 面向维护者的说明
├── agents/
│   └── openai.yaml       # Codex UI 元数据与默认调用方式
├── prompts/              # 唯一提示词原文与检索元数据来源
└── evals/
    ├── eval.yaml         # skill-up 评测配置
    └── cases/            # 调用、查找、适配、组合等回归用例
```

## 新增提示词

在 `prompts/` 中创建语义明确的 Markdown 文件，并使用以下 frontmatter：

```yaml
---
name: "提示词名称"
description: "说明它解决什么问题，以及适用场景。"
triggers:
  - "用户真实会说的典型触发语句"
inputs:
  - "{{VARIABLE}}: 必填或可选，并说明默认值"
---
```

正文必须在移除 frontmatter 后仍可直接使用，并明确任务、必要约束、成功标准和输出格式。一个文件只承载一个稳定意图。新增文件后不需要在 `SKILL.md` 或 README 维护第二份提示词清单。

## 验证

在本目录运行：

```bash
rtk skill-up validate evals/eval.yaml
rtk skill-up run evals/eval.yaml
```

评测至少覆盖按名调用、按场景查找、轻量适配、组合和无匹配处理。新增一种路由或关键行为时，同步增加一个能够在该行为回退时失败的用例。
