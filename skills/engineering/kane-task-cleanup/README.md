# kane-task-cleanup · 任务清理

任务或会话结束后，由你显式调用 `$kane-task-cleanup`。默认清理本次任务已核实的一次性临时文件，无需再选档位。Agent 先核实归属、用途和占用，说明保留成果与拟执行动作，再永久删除符合条件的文件。创建文件时无需预先分类或登记。

## 选择清理范围和程度

- **范围**可选本次任务（默认）、当前会话、指定 Goal 或项目。范围有歧义时先只读盘点，再提供具体选项；无法定位任务时才先询问定位信息。
- **程度**默认清理一次性脚本、测试数据和输出。「只保留成果」另包括可重建的一次性环境、已替代的过程文件和旧产物；也可指定类别、路径或清单编号。
- **只看清单**可说「先盘点」，全程只读，不删除文件或停止后台任务。

敏感副本、Git 已跟踪文件、归并或脱敏、停止后台任务，需要具体对象和动作的授权；已有明确授权直接沿用。例如「停掉刚才为烟测启动的服务」能唯一定位实例时，无需再确认 ID。未要求停止且不占用待清理文件的后台实例会保留。尚未决定的范围、文件和后台事项合并询问，不重复问已答问题；后续只有新出现的必要信息或动作变化才追问。独立且已获授权的清理可以先完成。

## 用法

```text
使用 $kane-task-cleanup。
```

```text
使用 $kane-task-cleanup，只保留这次任务的成果。
```

```text
使用 $kane-task-cleanup，清理这个 Goal 的过程文件，只保留最终报告和交付所需的文件。
```

```text
使用 $kane-task-cleanup，只停掉刚才为烟测启动的服务。
```

跨任务清理需要能定位到对应的记录或产物路径。正式测试、仍在使用的文件和归属不明的对象会保留；普通未知项说明原因即可，你点名的对象缺少核实信息时才会询问。清理对象限本地任务文件与本次启动的后台实例。

## 依赖和输出

复制整个技能目录即可使用。盘点需要运行时能读取相关任务记录。执行清理时需有删除文件的权限，停止后台任务时需能查询和停止指定实例。

结果直接在对话中汇报，区分已删除、此前已不存在、已移入废纸篓、保留或待确认、失败，并说明跳过原因和记录覆盖边界。只有明确要求使用废纸篓时才移动文件。若停止了后台任务，同时汇报实例的核验结果。
