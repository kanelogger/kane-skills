# kane-task-cleanup · 任务清理

任务或会话结束后，由你显式调用 `$kane-task-cleanup`。Agent 根据已有记录只读盘点，收到确认后才执行。创建文件时无需预先分类或登记。

## 收尾三问

1. **清理哪个范围？** 本次任务（默认）、当前会话、指定 Goal 或指定项目。
2. **文件要清到什么程度？** 看过候选清单后，选择清临时文件、只保留成果、按编号处理或只看清单。一次性环境和已被替代的旧产物可纳入「只保留成果」，敏感调试副本需点选编号。
3. **哪些后台任务可以停止？** 从已核实由本次任务启动的服务、监听器和其他后台任务中选择，或保持运行。

已说清的范围直接沿用。文件与后台任务都有候选时，两项在同一轮分别确认。某一类没有候选时跳过对应确认。

## 用法

```text
任务做完后，使用 $kane-task-cleanup 清理这次产生的临时脚本和测试数据。
```

```text
使用 $kane-task-cleanup，清理这个 Goal 的过程文件，只保留最终报告和交付所需的文件。
```

```text
使用 $kane-task-cleanup，只停掉刚才为烟测启动的服务。
```

也可以说「先盘点」，只查看候选清单。跨任务清理需要能定位到对应的记录或产物路径。正式测试、仍在使用的文件和归属不明的对象会保留。清理对象限本地任务文件与本次启动的后台实例。

## 依赖和输出

复制整个技能目录即可使用。盘点需要运行时能读取相关任务记录。执行清理时需有移动文件的权限，停止后台任务时需能查询和停止指定实例。

结果直接在对话中汇报，包含已清理项、恢复位置、保留项和跳过原因。若停止了后台任务，同时汇报实例的核验结果。
