# 任务清理

用任务记录判断每个对象的归属和用途。清理前核对要保留的内容，执行后回读实际状态。

## User Input Tools

1. **优先用内置的用户输入工具**：如果当前 agent 运行时提供了这类工具——比如 `AskUserQuestion`、`request_user_input`、`clarify`、`ask_user`，或任何等价工具。
2. **回退到纯文本**：如果没有这类工具，就输出一条带编号的纯文本消息，请用户针对每个问题回复所选的编号或答案。
3. **批量提问规则**：
   - 如果工具支持**一次调用提多个问题**（例如 `AskUserQuestion`）：**把所有适用问题合并成一次调用。不要拆成多次调用。**
   - 如果工具**一次调用只能问一个问题**（例如单次提问的 `clarify`）：按优先级顺序，**一次问一个问题**。

此规则适用于本技能和随附参考文档。使用当前运行时提供的等价工具，并遵守其权限要求。

## 1. 确定清理范围

用户显式调用 `$kane-task-cleanup` 后，盘点已结束的任务或会话。交付、调试或复验还在进行时，等对应工作结束。盘点使用已有记录，文件创建时无需登记。

沿用用户指定的本次任务、当前会话、Goal 或项目。没有指定范围时，默认采用可唯一识别的本次任务。范围有歧义时先问清，再盘点对应文件。指定会话或 Goal 时，用可见记录或授权来源确定它包含哪些任务。缺失的部分记为未覆盖。把会话、Goal 当作定位产物的线索，保留会话历史和 Goal 状态。

## 2. 盘点并核实归属

先核对用户确认的交付物及其使用、运行、复现所需文件。保留项目源代码、正式测试和夹具、用户输入、任务开始前的修改、其他活动任务仍需要的资料，以及共享数据、项目配置、凭据源和版本控制数据。共享数据库中的记录和远端资源交由对应系统的清理流程处理。

从范围内的写文件记录、命令输出、测试运行 ID 或专属临时目录定位候选，包括有任务记录的项目外临时路径。若有先前的移动记录，核对实际存放路径和对象身份。需要时查基线、Git 状态和引用。名称、后缀、修改时间、未跟踪或忽略状态只用于发现候选。混合目录逐项核实。

| 候选 | 核对依据 |
| --- | --- |
| 临时脚本、测试数据和输出 | 烟测脚本、隔离测试库、日志、截图、覆盖率等确属一次性用途，且已无验收或复验依赖。 |
| 一次性执行环境 | 本次任务为验证安装的 `node_modules`、虚拟环境和测试专用缓存，须有记录证明其归属。确认能按保留的清单和锁文件重建，并核对是否仍被交付物或其他任务使用。 |
| 敏感调试副本 | 单列含登录状态或真实样本的抓包、浏览器状态导出和测试转储。只报告路径与敏感类型，避免展示内容。需要保留排查价值时，将「保留脱敏副本，再删除原件」作为具体动作供确认。撤销凭据另走对应流程。 |
| 已替代的过程文件和旧产物 | 查验现行成果及其依赖，确认过时计划、草稿、旧构建包、演示导出或演练副本已被替代，且仍有价值的内容已承接。保留唯一的决策、复现步骤、验收证据或仍用于回滚的版本。需归并时列出内容及目标位置。单独标注 Git 已跟踪的过程文件。 |

有服务、监听器、浏览器自动化实例、监控任务或后台脚本的启动记录时，读[停止临时服务和后台任务](references/stop-services.md)做只读核实。文件范围扩大时，停止范围仍限本次任务。用户明确只停后台任务时跳过文件盘点，明确只处理文件时跳过后台核实。

## 3. 应用用户选择的清理程度

按用户指定的档位、文件类别或路径筛选候选。仅调用技能或只说「清理一下」而未指定程度时，有候选才请用户选择。列出保留的成果和候选编号，标明路径、归属依据及拟采取的动作。默认档位只作建议。

- **清临时文件（默认）** — 清理一次性脚本、测试数据和测试输出。
- **只保留成果** — 在清临时文件的基础上，再清理确认可重建的一次性环境、已替代的过程文件和旧产物。
- **指定编号** — 只处理用户点选的项目。
- **只看清单** — 保留文件。

用户明确要求「只保留成果」「清临时文件」或删除指定类别、编号或路径时，直接删除范围内同时满足以下条件的候选，无需再次确认。

- 有任务记录证明对象归属，且已核实当前无人使用，也无交付、复现或其他任务依赖。
- 对象是一次性文件、可重建的环境，或已被替代且没有独有价值的过程文件或旧产物。
- 对象为本地、非敏感且非 Git 跟踪文件。

敏感副本、Git 已跟踪的过程文件、归并或脱敏，需要针对具体路径和动作的明确授权。用户已给出该授权时直接沿用。共享数据按第 2 节保留。归属或用途无法核实的对象保留并说明原因。若它是用户点名要求清理的对象，先请用户补充核实所需的信息。

## 4. 单独确认要停止的后台任务

需要停止时，列出已核实的实例标识、用途和停止方式，取得用户针对具体实例和动作的授权。仅要求盘点时提供只读结果。文件和后台任务都有待确认项时合并提问。已获授权且不依赖待停实例的文件可以先处理。

缺少回复、选择含糊或取消时保留对应对象。需要更改已获授权的具体对象或动作时重新确认。

## 5. 执行并验证

1. 按第 3、4 节的授权执行。获准归并或脱敏时，先完成并核验保留的内容，再删除原件。后台任务单独获准后，先停止依赖待清理文件的实例并确认退出。仍被使用或依赖的路径保留。
2. 动手前复核每项实际路径、文件身份、边界和占用情况。路径状态变化、父路径越界或目标身份存疑时跳过。符号链接和目标是不同对象，只处理已核实归属的链接本身。仅在全部内容均获准删除且无嵌套仓库、挂载点或其他任务文件时，才递归删除整个目录。
3. 逐项永久删除核实后的路径。只有用户明确要求移入废纸篓时才使用废纸篓。删除受限或失败时报告阻碍，禁止用移动到其他目录代替删除。向工具传入明确路径，用系统命令时通过参数数组传值。
4. 回读处理前后的路径，核实删除结果或废纸篓去向，检查交付物及必要文件仍在。涉及 Git 工作区时，对比清理前后的状态，确认差异只来自获准的清理。分别记录「已删除」「此前已不存在」「已移入废纸篓」「跳过」或「失败」。

## 完成标准

在对话中给出范围和程度、保留的成果及各候选的核验结果。只有执行删除且回读确认对象消失，才记为「已删除」。移入废纸篓的对象单列。已停止的后台任务附核验结果。用户未确认的项标为待确认或保留。记录不足时说明覆盖到了哪里。
