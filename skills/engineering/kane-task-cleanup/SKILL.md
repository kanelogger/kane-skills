# 任务清理

先核实成果和候选，再按已有授权处理；只把确实需要用户决定的事项合并询问，执行后回读实际状态。

## User Input Tools

1. **优先用内置的用户输入工具**：如果当前 agent 运行时提供了这类工具——比如 `AskUserQuestion`、`request_user_input`、`clarify`、`ask_user`，或任何等价工具。
2. **回退到纯文本**：如果没有这类工具，就输出一条带编号的纯文本消息，请用户针对每个问题回复所选的编号或答案。
3. **批量提问规则**：
   - 如果工具支持**一次调用提多个问题**（例如 `AskUserQuestion`）：**把所有适用问题合并成一次调用。不要拆成多次调用。**
   - 如果工具**一次调用只能问一个问题**（例如单次提问的 `clarify`）：按优先级顺序，**一次问一个问题**。

此规则适用于本技能和随附参考文档。使用当前运行时提供的等价工具，并遵守其权限要求。

## 1. 沿用意图，补齐默认值

仅在用户显式调用后执行。沿用本轮及上下文中仍适用的范围、动作和授权；交付、调试或复验未结束的部分暂不清理。

| 用户表达 | 处理方式 |
| --- | --- |
| 仅调用技能、「清理一下」或「清临时文件」 | 默认清理可唯一识别的本次任务的一次性临时文件，不再询问档位。 |
| 「只保留成果」 | 另纳入可重建的一次性环境、已被替代的过程文件和旧产物。 |
| 指定类别、路径或清单编号 | 仅处理指定对象，仍须通过下述核实。 |
| 「先盘点」「只看清单」 | 全程只读，不删除文件或停止实例，也不要求用户立即决定。 |
| 「只停后台任务」或「只处理文件」 | 只盘点和处理对应对象。 |

范围可为本次任务、当前会话、指定 Goal 或项目。用已有记录定位产物，创建文件时无需登记；会话历史和 Goal 状态保持不变。范围有歧义时，仅在已有记录涉及的任务和路径内做只读盘点，将具体范围选项留到第 3 步合并询问；无法定位任何任务或路径时，只问缺少的定位信息。记录缺失的部分标为未覆盖，不推定为可清理。

## 2. 核实成果与候选

先保留交付物及使用、运行、复现所需文件，以及源代码、正式测试和夹具、用户输入、任务开始前的修改、其他活动任务资料、共享数据、项目配置、凭据源和版本控制数据。共享数据库记录与远端资源交由对应系统处理。

从范围内的写文件记录、命令输出、测试运行 ID 或专属临时目录定位候选，可包含有记录的项目外路径。核对移动后的实际位置，按需查基线、Git 状态和引用。名称、后缀、时间、未跟踪或忽略状态只用于发现，不能证明可删；混合目录逐项核实。

每项须确认归属、用途已结束且无交付、复验、回滚或其他任务依赖，再按类型核对：

- **一次性临时文件**：烟测脚本、隔离测试数据、日志、截图、覆盖率等，不含正式测试和验收仍需的证据。
- **一次性环境**：确为本次验证安装的依赖、虚拟环境或缓存，且能用保留的清单和锁文件重建。
- **过程文件和旧产物**：现行成果已承接有价值内容，保留唯一的决策、复现步骤和验收证据；需归并时列明内容及目标位置。
- **敏感调试副本**：只报告路径与敏感类型，不展示登录状态或真实样本；需留排查价值时提出「保留脱敏副本，再删除原件」。凭据撤销另走对应流程。

有本次任务的后台启动记录且未限定只处理文件时，读取[停止临时服务和后台任务](references/stop-services.md)核实实例及文件占用。用户要求停止，或实例占用待清理文件时，才将停止动作列入第 3 步；其他实例保留并汇报。文件范围扩大不扩大后台停止范围。

## 3. 统一决定：执行、询问或保留

只看清单时到此汇报核实结果。其余候选按以下顺序处理：

| 情况 | 决定 |
| --- | --- |
| 不在所选范围或程度内、属于保留项、仍有依赖，或归属和用途未核实 | **保留**并说明原因。用户点名的对象缺少可补充的信息时，才列入问题。 |
| 敏感副本、Git 已跟踪文件、归并或脱敏、停止后台实例 | 已有针对具体对象和动作的授权则**执行**；否则**询问**。 |
| 范围明确且核实通过的其余本地文件 | **执行**所选程度内的删除。默认程度也适用，无需再选档位或确认清单。 |

自然语言明确要求动作且能结合记录唯一定位对象，就算具体授权，例如「停掉刚才为烟测启动的服务」；无需用户重述实例 ID。同样，已明确要求删除的具体敏感副本或已跟踪文件，无需重复确认。授权不能替代归属与依赖核实。

执行前简短说明范围、保留成果和拟执行动作。把当前能确定的范围歧义、特殊文件处理、后台停止合并成一轮问题：列出编号、路径或实例标识、依据、具体动作及需用户决定的点。只询问未决事项，不重问档位或已答问题；只有答复引出新的必要信息、对象或动作改变时才继续问。

已确定范围内、已获授权且不依赖待决项的工作可先做。范围仍有歧义的对象、未回复或答复含糊的项保持不动；不为归属不明的普通候选追问，也不为无候选的任务发起选择。

## 4. 执行并验证

1. 获准归并或脱敏时，先完成并核验保留内容；获准停止实例时，先正常停止并确认退出，再清理它使用的文件。仍有依赖的路径保留。
2. 动手前复核实际路径、身份、边界和占用。状态变化、父路径越界或身份存疑时跳过。符号链接只处理已核实的链接本身；整个目录仅在所有内容均获准且无嵌套仓库、挂载点或其他任务文件时递归删除。
3. 默认逐项永久删除；仅在用户明确要求时移入废纸篓。受限或失败时报告阻碍，不用移到其他目录代替删除。向工具传入明确路径，系统命令通过参数数组传值。
4. 回读路径核实结果及废纸篓去向，检查交付物和必要文件仍在；涉及 Git 时对比前后状态，确认差异仅来自获准清理。

## 完成标准

在对话中汇报范围、程度、保留成果及处理结果；记录不足时说明覆盖边界。候选分别标为「已删除」「此前已不存在」「已移入废纸篓」「保留／待确认」或「失败」，跳过项附原因。只有实际删除并回读确认消失才记为已删除；后台实例只有核实退出才记为已停止。未决项不影响报告已完成部分。
