# Kane Agent Harness

把自己的开发方式带进下一个项目，也能在项目已有团队规范时逐条接入。技能随包提供协作、需求与规格、工作流、独立审阅、工程、测试、集成、经验库、环境清单等正文。角色、任务、ADR、子系统等专题按需采用。日常工作的入口是项目自己的 `AGENTS.md`。

## 调用

```text
使用 $kane-agent-harness 初始化当前项目，采用默认协作规范。
使用 $kane-agent-harness 把需求与规格接入当前项目，沿用团队现行的 PRD。
使用 $kane-agent-harness 将已采用的规格来源换到团队迁移后的 PRD，预览入口和引用的变化，保留原有需求正文。
使用 $kane-agent-harness 为这个项目接入独立审阅，先读 CONTRIBUTING.md，把缺的规则放在这里。
使用 $kane-agent-harness 升级当前项目的独立审阅，保留单模型环境的例外。
使用 $kane-agent-harness 只在这个项目停用独立审阅，保留原有团队条款。
使用 $kane-agent-harness 修改共享模板，以后新项目的审阅记录应写明结论针对的版本。
```

尚未安装时，可在上述请求中给出本地技能目录的绝对路径。项目操作需要目标目录，修改共享模板需要可维护的技能源码目录。运行脚本需要 Bun 1.3.8 或以上版本（本机实测 1.3.14），无额外包依赖。文件写入面向 macOS 和 Linux。

## 项目会得到什么

首次初始化采用默认部件，生成项目入口、规范正文和 `.agents/harness.json`。采用记录随项目入库，保存采用位置、旧版标准正文、采用时的适配结果及例外原因；团队已有规则可直接引用。后续升级据此比较项目现状和新版正文。Markdown 文档用不可见边界标记区分技能维护的段落和团队内容。其他项目通过显式升级接收共享模板变更。

从根 `AGENTS.md` 的“需求与规格”进入产品行为的权威来源。新项目默认生成 `specs/requirements.md`，用目标与范围、输入与输出、约束与边界、验收条件四项写清一条需求。已有项目优先链接团队现行 PRD 或需求索引，原文继续由团队维护。已采用旧版 harness 的项目也可单独启用 `requirements`。

默认工作流要求执行者从现行规格提取行为变更的验收条件。项目已采用独立审阅且改动达到触发条件时，实施前审计划，交付前审最终差异和运行证据。团队更换现行规格时，项目导航和标准工作流跟随新来源。旧版同时保留作档案时，执行 Agent 会核实定制片段中哪些链接应保留历史版本。

静态核验覆盖已采用正文、完整 `AGENTS.md` 渲染出的导航、本地链接和未确认的改动。代码围栏、`hidden`、`template`、未带 `open` 的 `dialog`，以及内联样式中生效的字面量 `display: none`，都可能遮住入口。遇到这些情况，预检会指出导航不可见并保留原文件。样式表、变量解析和脚本运行后的可见性需在目标客户端核实。在采用报告中分别说明结构检查、冷启动演练和业务命令的执行结果。实际模型、客户端权限及检查工具取决于目标环境。

执行步骤见 [SKILL.md](SKILL.md)，项目决策示例见[操作说明](references/project.md)，增删标准部件见[模板维护](references/templates.md)。

## 可选 · Herdr 配置推荐

如果你用 Herdr 开发，可以在目标项目中打开 Agent，复制下面的提示词，请它准备一套带只读任务侧栏的个人布局。布局准备好后，由你在 Herdr 中选择何时启用。

```text
请为当前项目配置一套可选的 Herdr GUI 布局。先读 `~/.config/herdr-app/AGENTS.md` 和项目根目录的 `AGENTS.md`。如果项目有 `agents.yml`，用它理解角色分工。任务进度和审阅结论以项目的任务记录为准。

沿用 Herdr 的常用布局。左侧保留空间和助手列表，中间保留标签页和终端，右侧加一个只读任务侧栏。侧栏跟随当前空间，只显示这次任务实际用到的阶段。让我能查看进度、跳到相关终端、打开计划、测试结果和审阅证据。找不到记录时，显示「暂无任务记录」。终端结束后，审阅状态仍以审阅记录为准。

把布局保存为一套新的个人布局，名称用「项目名 · 协作」。保留现有配置和当前布局。`layout.clone` 会立即切换，请直接创建新的布局文件。完成后告诉我布局叫什么、如何在布局列表里选中它，由我自己决定何时启用。
```
