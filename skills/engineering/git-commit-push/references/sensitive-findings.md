# 敏感信息发现与确认

仅在发现疑似敏感内容或有检查缺口时读取。所有模式遵守本节，交互工具使用入口的 User Input Tools 规则。

- 先完成候选复核，只呈现路径、可用时的行号、发现类型和检查缺口，不回显敏感取值。说明提交会将内容写入 Git 历史；已获推送授权时说明还会发布到目标远端。
- 明确说明确认要求来自本节，并链接本文件或本技能的 `SKILL.md`。直接询问是否仍提交这些已经复核的内容；只有已选择推送时才将推送纳入问题，不扩大授权。
- 用户明确同意才继续；笼统的“把改动都提交／推送”不等于同意新发现。此前同意已覆盖同一发现、同一内容和同一目标时可复用，不重复提问。
- 拒绝则取消；没有回答或含糊则等待，期间不提交、不推送，保持工作区和索引不变。不要静默删除发现、取消暂存或改成部分提交。
- 候选变化后重新检查；仅新发现或发布范围超出现有同意时重新询问。即使用户同意提交敏感内容，也不得将取值写入提交信息或最终报告。
