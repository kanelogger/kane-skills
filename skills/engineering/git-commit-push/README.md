# git-commit-push

安全完成一次提交或提交并推送流程；仅要求提交时不会推送。只暂存当前任务相关文件，依据暂存 diff 和已有任务材料生成 Conventional Commits 1.0.0 提交信息，提交后核对 Git 状态，并仅在请求包含推送授权时推送当前分支。

提交正文固定包含改动、原因、验证方式与结果、回滚方法。本技能只记录已有验证证据，不主动运行测试、构建、lint、类型检查或功能验收，也不执行回滚；提交范围复核、敏感信息检查、Git 状态核对和仓库原有 hooks 仍保留。

在 Codex 中输入 `$git-commit-push` 显式调用。

## Use when

- 完成一个开发任务后，需要提交并推送相关改动。
- 工作区同时存在其他修改，需要严格控制本次提交边界。
- 希望提交信息包含规范标题，并写清改动、原因、验证方式与结果、回滚方法。
- 希望提交信息优先遵循用户指定语言，否则根据项目规范、最近提交和当前对话选择语言。

## Safety

- 只使用显式路径暂存，禁止 `git add .`、`git add -A` 和宽泛通配符。
- 提交前复核全部 staged paths 与 hunks，发现无关内容立即停止。
- 每次提交前检查文件内容和暂存区中的 key、token、账号密码、私钥等敏感信息；发现疑似信息或无法检查的内容时，脱敏说明并询问用户。明确同意才继续，拒绝则取消，未回答则暂停；无发现时正常继续。
- 默认禁止 amend、跳过 hooks、切换分支和 force push。
- 无法可靠判断上游远端时，推送前停止并请求用户确认。

## Example

`Use $git-commit-push to commit and push the changes from this task.`

## Commit message

正文按所选语言依次记录以下四部分：

- **改动**：做了什么，影响哪些行为或文件，以暂存 diff 为准。
- **原因**：来自已有任务材料或 diff 的动机、约束与权衡；依据不足时询问用户。
- **验证**：已有命令或操作、实际结果及未验证项，注明用户提供的结果来源。没有执行证据就写“未验证（无已有执行记录）”；建议步骤标明“未执行”，没有可靠方法时写“验证方式待补充”。失败、阻塞、覆盖不足和旧版本记录均如实说明，不为补齐正文运行验证。
- **回滚**：具体撤销步骤及限制。纯代码或文档改动可记录 `git revert <本次提交哈希>`，最终报告使用实际哈希；涉及数据、外部配置或部署时补充恢复顺序与前置条件，未知项标明“恢复步骤待补充”。只记录、不执行。

## Output

提交哈希、提交标题、已提交文件、Git 状态核对结果、正文中记录的验证方式与结果、使用实际提交哈希的回滚方法，以及保留的无关修改。获授权推送时另报分支、远端与同步结果；推送失败会与提交成功分开报告。用户确认使用当前运行时的输入工具，缺失时回退到编号文本。

## Completion

提交正文四部分齐全，验证记录及缺口真实、回滚步骤与限制明确；提交内容与复核候选一致，无关改动被保留，敏感信息闸门已通过。本技能未主动执行改动验证或回滚。仅提交时核对本地 Git 状态；获授权推送时另确认远端同步。最终报告包含实际提交哈希和对应回滚方法。
