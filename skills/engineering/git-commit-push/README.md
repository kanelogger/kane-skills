# git-commit-push

按选定深度完成当前任务的 Git 提交，并根据单独授权决定是否推送。只暂存当前任务相关内容，保留无关修改；提交后核对 Git 状态，推送后核对远端同步结果。

在 Codex 中输入 `$git-commit-push` 显式调用。

## 两项独立选择

1. **执行深度**：快捷、全面或深度。
2. **交付动作**：仅提交或提交并推送。

复用当前请求中已明确给出的答案，只询问未回答的问题。优先使用当前运行时的用户输入工具；支持批量提问时一次问完，否则依次提问，没有输入工具时使用编号文本。执行深度不代表推送授权。

| 深度 | 执行范围 | 提交信息 |
| --- | --- | --- |
| 快捷 | 仅根据精确的暂存 diff 概括改动；不主动运行检查、不做代码评审，也不查询历史提交来决定语言 | 简洁的 Conventional Commit 标题，可附简短改动摘要；不要求原因、验证或回滚正文 |
| 全面 | 审阅变更内容，按需读取理解变更所需的上下文；不主动运行测试、类型检查、lint 或构建 | Conventional Commit 标题，正文包含改动、原因、已有验证和回滚四部分 |
| 深度 | 在全面模式基础上，评审相关调用路径，并按改动需要选择现有测试、类型检查、lint 或构建 | 与全面模式相同的四部分正文，验证部分记录实际执行结果 |

全面或深度模式发现未解决的重要正确性或安全问题时，停止提交并报告原因；深度模式的相关检查失败、受阻时同样停止，不会自动修复源代码。各模式均保留提交范围与敏感信息检查、Git 状态核对和仓库原有 hooks。

## 提交信息

语言依次采用用户明确指定、当前已知的仓库提交规范、当前请求语言；没有可靠信号时用英文，不为此读取历史提交。

全面与深度模式的正文按所选语言依次包含：

- **改动**：以暂存 diff 为准，说明改了什么及影响范围。
- **原因**：说明已有任务材料或变更上下文支持的动机、约束与权衡；依据不足时如实标明，不为补齐正文追加提问。
- **验证**：如实记录已有或本次执行的命令、操作、结果及未验证项，注明用户提供证据的来源。全面模式没有执行证据时写明未验证，不为补齐正文主动运行检查；深度模式记录所选检查的实际结果。
- **回滚**：记录具体撤销步骤、前置条件和限制。纯代码或文档改动可使用 `git revert <本次提交哈希>`，最终报告替换为实际哈希；数据、外部配置或部署另说明恢复顺序。只记录，不执行回滚。

## 安全边界

- 只使用显式路径暂存，禁止 `git add .`、`git add -A` 和宽泛通配符；提交前复核所有暂存路径与变更块，存在无关内容时停止。
- 提交前检查文件内容和暂存区中的密钥、token、密码、私钥等敏感信息。发现疑似信息或无法检查的内容时，脱敏说明并询问用户；只有明确同意才继续，拒绝则取消，未回答则暂停。
- 仅在用户明确选择或要求“提交并推送”时推送当前分支；无法可靠判断上游远端时先询问用户。
- 未经明确要求，不 amend、不跳过 hooks、不切换分支、不 force push。原有 hook 失败时报告并停止，不自动修复或重试。

## 示例

`使用 $git-commit-push，快捷模式，仅提交当前任务的改动。`

`使用 $git-commit-push，深度模式，提交并推送当前任务的改动。`

## 输出与完成标准

报告所选深度与交付动作、实际提交哈希、标题、已提交文件、Git 状态及保留的无关修改。全面与深度模式另报告验证记录、缺口和使用实际哈希的回滚方法；获授权推送时另报告分支、远端与同步结果。提交成功但推送失败时分别说明。

提交内容必须与复核范围一致，敏感信息检查与原有 hooks 已通过；深度模式的相关检查通过且不存在未解决的重要正确性或安全问题。仅提交时完成本地状态核对，提交并推送时另确认远端同步。
