# simplify-codebase

用证据驱动的方式为代码库“减熵”：识别并安全移除死代码、重复状态、冗余 API、无主抽象、过期兼容逻辑和已经失效的设计记录。目标是减少系统需要长期维护的一致性义务，而非单纯追求删除更多代码。

提示词事例：
```md
Scope: 基于 /skill:simplify-codebase 代码规范,全面简化当前代码库。
Divide: 先按真实的大模块和所有权边界拆分任务，启动并发子代理分别清扫。主代理负责协调跨模块问题、整合修改并完成最终验证。
Reduce: 重点处理AI代码中不必要的抽象、重复定义、冗余接口与状态、无意义的变量和转发层、过度泛化及无效兼容代码。目标不是单纯减少行数，而是让模块职责、类型定义、接口和数据流更直接、更清晰、更容易维护。
Preserve: 允许子代理根据代码实际情况自主判断并直接修改，但要确认真实调用关系，避免改变现有行为或误删有效契约。不要只输出审计报告，完成所有高置信度的简化。
Verify: 最后运行仓库已有的测试、类型检查、Lint和构建，汇总实际修改、验证结果与剩余风险。
Optional workflow: 网页端Pro通读仓库并生成清理方案→Codex 按方案修改、测试与验证让全局审查与本地执行相互校验。
```


## 适用场景

- 审计代码库中可以删除或合并的复杂度，并按证据强度与收益排序。
- 清理没有生产消费者的接口、配置、事件、依赖或兼容路径。
- 合并描述同一事实的重复状态、缓存、格式或状态机。
- 判断抽象层、包装层、扩展点和自建基础设施是否仍有实际所有者。
- 清理由已下线功能遗留的测试、文档、Schema、配置或设计记录。
- 对另一个分支、PR、任务或智能体产生的简化发现进行复核与整合。

不适用于普通代码审查、项目上手、纯风格重构或性能调优。

## 工作模式

技能会先确定授权模式，再确定覆盖范围：

| 维度 | 模式 | 行为 |
| --- | --- | --- |
| 授权 | 审计（Survey） | 保持只读，调查候选项并输出排序后的证据，不修改仓库。 |
| 授权 | 变更（Change） | 在用户明确授权后实施已证明安全的删除或合并，并验证保留下来的契约。 |
| 范围 | 聚焦（Focused） | 围绕指定子系统、符号、状态机、依赖或疑似重复项进行完整追踪。 |
| 范围 | 广泛（Broad） | 对仓库或多个领域建立覆盖图，逐域检查并记录盲区。 |

删除仍可达的能力、公开接口、持久化格式或兼容路径属于产品决策。缺少明确授权时，技能只会说明影响并请求决策。

## 核心方法

1. 建立契约地图：追踪入口、配置、注册、分发、持久化、进程与协议边界。
2. 建立覆盖图：记录已检查的领域、生产路径、搜索证据和未解决盲区。
3. 构建证明记录：为每个候选项记录负担、可达性、存在理由、删除边界、行为后果、风险和验证方法。
4. 区分置信度与收益：高收益猜测不会排在证据充分的小型删除之前。
5. 垂直移除义务：同时处理声明、实现、注册、测试、文档、依赖和兼容残留，避免只删表层代码。
6. 分层验证：依次执行残留搜索、决定性检查、局部质量门、仓库级检查、边界对比和最终 diff 审计。

技能会特别保护授权校验、信任边界验证、安全隔离、可访问性、数据防丢、持久化兼容，以及确保异步任务真正静止的清理逻辑。

## 使用示例

```text
使用 $simplify-codebase 审计这个仓库，找出证据最充分的 5 个简化候选，不要修改代码。
```

```text
使用 $simplify-codebase 聚焦检查 src/runtime 的重复生命周期状态；确认安全后直接简化并运行相关测试。
```

```text
使用 $simplify-codebase 复核这个 PR 的“删除兼容层”结论，重点检查动态加载、外部消费者和存量数据风险。
```

```text
使用 $simplify-codebase 整合另一个分支中的简化发现，只保留在当前分支仍有证据支持的部分。
```

## 输出

审计模式通常交付：

- 覆盖范围与未检查盲区；
- 按置信度、收益、风险和可逆性排序的候选项；
- 每个候选项的消费者地图、契约证据、删除后果与最小验证方法；
- 被否决或尚未解决的重要候选，以及做出判断仍缺少的事实。

变更模式还会交付操作回执，包括变更边界、基线、已移除义务、涉及文件、实际净收益、行为变化、逐层验证结果、残余风险和回退路径。

## 目录结构

```text
simplify-codebase/
├── SKILL.md
└── references/
    ├── investigation.md
    ├── boundaries-and-lifecycle.md
    ├── execution-and-recovery.md
    ├── decision-records.md
    └── integrating-findings.md
```

- `SKILL.md`：模式选择、契约建立、证据标准、决策和交付要求。
- `investigation.md`：广泛审计、消费者分类、历史证据和候选排序方法。
- `boundaries-and-lifecycle.md`：信任边界、并发状态、资源生命周期与静止性证明。
- `execution-and-recovery.md`：完整删除、分层验证、失败恢复与操作回执。
- `decision-records.md`：ADR、RFC 和设计记录的归属判断与安全整合。
- `integrating-findings.md`：跨分支、PR、任务或智能体结果的证据复核与合并。

## 判断标准

一次成功的简化必须减少真实的维护概念或一致性义务，并有能够暴露错误删除的验证手段。没有找到安全候选也是有效结论；代码行数减少本身不构成成功证据。
