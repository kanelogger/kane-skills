# 任务工作流程

规划、执行、审阅和交付任务时遵循本流程；测试范围与执行条件见 [测试约定](testing.md)。

## 理解上下文与澄清

- 按任务范围阅读目标代码、相关调用方或导出项、相邻代码惯例与受影响测试；局部修改只补足相关上下文，跨模块变更沿实际依赖扩大阅读范围。
- 从 [子系统索引](../docs/subsystems/README.md) 确定受影响职责及事实来源；涉及已有故障模式时查阅 [经验记录](../docs/lessons.md)。子系统文档提供入口，结论仍以本轮源码和验证为准。
- 实现做法相互冲突时，在遵守项目规则的前提下，根据局部惯例、新旧程度、测试覆盖与可靠性证据作出选择，记录尚未解决的重要冲突。
- 缺失信息会实质性影响正确性、安全性或实现方向时，先提问；其余情况说明合理假设后继续推进。
- 不同方案会带来不同的维护、兼容或运维结果时，说明重要取舍。

## 计划与验收清单

- 输出计划时同时输出验收清单，与需求逐项对应。每项写明场景、可观察的预期结果、验证方法或命令，以及待填写的结果和证据位置。
- 计划列明影响范围、要跑通的完整 E2E 链路、开发期间的相关测试、交付前回归范围及依据，并按测试约定判断是否触发项目全量；不适用的检查注明理由。
- 使用 [任务模板](../tasks/README.md) 保存计划与验收清单；需求或实现范围变化时同步更新，执行中逐项记录实际结果。
- 并行任务在记录中明确文件或模块负责人；共享工作区按文件分工，分别修改同一模块时使用独立 checkout/worktree。验收前汇总改动，在同一最终输入上集中回归；端口、临时栈、浏览器会话与证据目录按运行归属管理，具体机制见 [环境协议](../docs/agent-environment/network-filesystem.md)。

## 实现与推进

- 以最小但完整的变更满足需求，遵循现有命名、结构、错误处理、格式与测试风格。
- 删除因本次变更而失效的导入、变量、函数与文件；无关重构、格式调整和既有死代码清理不混入本次差异，重要问题另行说明。工作区保护与完整 diff 审阅按 [Git 规则](git.md) 执行。
- 在已授权、安全、可逆的本地范围内，持续完成实现、相关验证和结果核对，修复本次变更引发的问题。
- 遇到会实质性改变产品结果的未决事项、关键需求不明、缺少权限，或未获批准的破坏性、对外可见操作时，暂停并取得确认；权限与批准条件见 [安全规则](security.md)，提交与推送按 [Git 规则](git.md) 执行。

## 审阅先核对数据与结论

- Agent 审阅的第一步是检查数据和结论是否匹配，再评价方案、实现质量和验收是否通过。
- 对关键结论逐项定位原始数据、日志、测试报告或实际观察，核对代码版本、环境、时间、样本范围、单位和统计口径是否支持该结论；对比结果必须使用可比口径。
- 发现矛盾、缺失或过期证据时，先修正结论或补做验证。区分观察事实、推断与未验证项；失败、跳过或未覆盖的检查如实记录。
- 跨子系统、权限、迁移或验证工具的变更，在交付前使用独立审阅者核对最终 diff、所属子系统文档与证据；审阅者不参与该部分实现。记录发现、修复与复核结果。不可用时明确标注独立审阅未执行，不能以作者自检冒充。内部重构不改变职责、契约和失败行为时，无需改写子系统文档；行为变化须同次更新。

## 收尾与清理

- 按验收清单核对最终结果，完成 [测试约定](testing.md) 要求的回归；交付说明列出本次改动、验证证据与结果、仍存风险、未通过或未验证的事项，以及必须跟进的工作。只有证据足以支持时，才能宣称完成或通过。
- 结束任务时删除本次创建的临时测试数据、测试账号、上传文件和一次性验证脚本，停止自建服务并回收临时资源；按 run ID、记录 ID、路径或 project label 确认归属并核对清理结果。
- 保留纳入仓库的正式回归测试、可复用 fixture、维护中的测试工具及必要的脱敏验收证据。清理仅作用于本次临时产物，保护用户数据和其他任务资源；资源归属不明或清理失败时记录残留、原因和恢复方式。
- 按 [任务记录维护方式](../tasks/README.md) 归档必要的取舍并删除已完成任务记录。
- 检查本次是否出现可复用的失败经验；有证据的案例写入 [工程经验](../docs/lessons.md)，长期取舍写入 ADR。稳定规则仍在所属规则文件维护，可确定性检查的约束进入现有门禁并加入违规样例测试；没有新经验时无需新增记录。
