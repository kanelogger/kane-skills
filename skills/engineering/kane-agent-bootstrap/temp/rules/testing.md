# 测试约定

## 验证范围

纯文档或规则变化检查本地链接、命令一致性、规则冲突和完整 diff。涉及脚本行为时，运行相关测试，并至少验证一条 CLI → 关键处理 → 可观察输出及退出码的真实链路。Mock 只能提供辅助证据。

影响公共工具、全局依赖、检查基础设施，或无法可靠界定影响范围时，交付前基于最终输入运行一次 `pnpm check`。它覆盖 [当前 CI](../.github/workflows/ci.yml) 的文档与全部控制工具测试。相同输入上已通过的检查无需重复；验证后修改实现则重跑受影响检查。

## 当前入口

- `pnpm check:docs`：本地 Markdown 引用与根 package 命令引用。
- `pnpm test:unit`：Node 原生测试，覆盖环境诊断、文档门禁与技能固定来源恢复；临时 Git 仓库只在本地创建，不访问真实远端。
- `pnpm check`：上述两项的完整聚合命令。

本仓库没有业务应用，应用 E2E、数据库、视觉、浏览器和构建验收不适用。接入应用时应按真实调用链增加测试和 CI，覆盖页面或命令入口、关键处理、持久化结果回读，以及拒绝与失败路径。

## 证据与清理

记录验证输入、命令、退出码、覆盖范围、未执行与失败项。静态文件存在不能证明行为正确，本地通过不能描述成远程 CI 通过。

只清理本次 fixture、自建临时目录和可确认归属的服务。测试不写入生产系统、不读取真实密钥，不删除原工作区用户数据。真实外部技能恢复须有实际网络结果；本地 fixture 通过不代替远端可达性验证。
