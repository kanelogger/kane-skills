# 当前能力核对

[project.yml](../../project.yml) 声明项目需要什么；本次探测说明当前环境能做什么；用户授权和环境权限决定哪些操作可以执行。三者分别核对。模板没有提供自动诊断工具，以下步骤由执行者或采用项目已有工具完成。

## 按任务核对

先确定本任务需要的能力，再选择范围最小的核对方式。读取配置、检查文件或获取工具版本优先使用无副作用的方法；网络、启动服务、写入和安装工具遵循当前任务授权及环境权限，不为探测额外扩大操作范围。

| 能力 | 可采用的证据 | 不能据此推断 |
| --- | --- | --- |
| 文件和配置 | 当前工作区的可读性、格式及实际内容 | 文件正确、允许修改其他路径或旧报告仍有效 |
| 工具链 | 本轮版本输出及与[登记来源](commands.md)的核对 | 依赖完整、项目可以构建或测试通过 |
| 网络与外部工具 | 对任务所需目标的实际访问结果、工具提供的当前能力 | 其他目标可达、允许外部写入或认证永久有效 |
| 本地服务 | 当前 owner、进程或实例标识、就绪检查与输入版本 | 其他工作区服务可复用、完整业务链路已通过 |
| 技能与外部工具 | 登记来源、可分发内容的版本校验，或远端接口的本次能力证据 | 来源可信、适合任务或已被客户端加载；远端服务版本可固定 |
| 测试与 CI | 对应输入、环境、范围和实际运行结果 | 未运行的测试、远端检查或发布也已成功 |

## 保存与恢复

需要跨会话保留的能力结果写入[任务记录](../../tasks/README.md)，至少包含：核对对象、工作区、核对者、时间、实际证据、结论及未覆盖项。使用“未检查、可用、不可用、不适用”等明确状态，失败和未检查不能写成可用。

不保存令牌、认证头、完整环境变量或含敏感信息的原始输出。必要日志先脱敏，再按[任务规范](../../tasks/README.md)的归档约定保存。

恢复任务时核对仍适用的用户授权、当前环境权限、工作区归属、网络和服务状态；已有授权仍适用时继续执行，不因换会话要求重复批准。环境、工具版本、输入或认证发生变化时，重做受影响的核对。旧报告提供排查线索，不能作为当前权限或健康结论。
