本说明记录 prototype-03 作为个人全栈 AI 开发协作底座的内容取舍，不增加第二套执行规则。个人协作方式和工程底线跨项目复用，技术栈与运行事实由各项目决定。采用方式与信息分工见 [README](../README.md)。本目录可独立复制，阅读和采用不依赖 prototype-01 或 prototype-02 的文件。

## 修正与删除

- 补齐唯一 [经验入口](../LESSONS.md)，以易漏场景索引指向所属规范，保留本地复盘格式，不重复维护操作规则。
- 所有导航指向本目录已有文件，模板链接按实际位置维护；变更统一按工程标准和工作流程核对。
- 未提供诊断器、文档门禁、技能管理器、测试工具或 CI，不保留它们的已实现声明、命令、退出码和源码链接。环境说明统一写为采用要求或待填写记录。
- 去除固定 Node、pnpm、JavaScript ESM 及绑定语言的代码风格偏好；不要求数据存储名、查询引擎、数据管道或 DuckDB 目录。实际版本与风格由采用项目已有配置维护；个人协作约定集中在根 AGENTS.md，不随技术栈开放而删除。
- 不导入旧项目的测试通过、事故、发布记录或技能安装状态。
- 项目清单由 Agent 直接读取；项目环境集中声明，版本与命令定义引用实际配置。归档要求统一放在任务规范中，不另维护一份归档规则。
- 按风险选择自动回归、手工对照和替代证据；遥测采集与业务上传分别限定范围。可分发技能的版本与安装校验不套用到无法固定版本的远端工具。
- 任务模板只保留接手与验收所需的基本信息，普通无关项可以删除；必需检查的缺口和实际风险仍须说明。已有命名、结构及测试惯例优先，不另加一套个人风格规则。
- 日常短任务在会话中完成目标、修改、相关验证与交付；短暂委派不自动触发持久任务文件。复杂或高风险任务按需增加计划和独立审阅，不把五种角色、ADR、PR 或共享状态变成固定关卡。

## 后续维护

新项目先核对当前规则与源码，再合并所需内容。确定性约束优先接入已有检查并验证反例，语义取舍通过独立证据审阅。普通经验是否晋升为规则依据适用性、独立案例与影响，不机械要求固定次数；关键安全约束不必等待重复事故。

修改结构时同时核对本地链接、模板路径与命令声明。文档检查不能替代真实开发验收；实际采用结果按 [开发演练](agent-environment/development-rehearsal.md) 留证。
