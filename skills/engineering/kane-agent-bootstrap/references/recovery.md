# 应用收据与失败恢复

目录：[写入前](#写入前) · [收据与部分失败](#收据与部分失败) · [恢复条件](#恢复条件) · [冗余验收](#冗余验收)

## 写入前

计划采用技能入口所述的 JSON 操作结构。应用先核对全部候选，再按当前实际内容写入；冲突预检失败不修改计划中的文件。写入期间仍可能有其他执行者变化，遇到冲突停止后续项并保留现场。

收据保存本轮修改前文本及前后摘要，用于恢复规则和配置。只将非秘密的普通文本纳入计划；实际 `.env`、凭据和私有状态使用项目已有配置方式处理，不能复制进计划或收据。合并 `.agents/state/` 等实际收据位置的忽略规则，限制本机访问；忽略规则不保护已跟踪文件，也不代替内容审查。

本机权限或描述符能力不足时保留候选内容和明确原因，不改用宽泛覆盖。参数、路径和文件内容都按数据处理；CLI 不执行计划中的任何程序或命令。

## 收据与部分失败

`apply` 真正修改前持久保存收据，默认在目标项目根 `.agents/state/bootstrap/<uuid>.json`。可用 `--receipt` 指定项目内相对路径。dry-run、零变化和预检冲突不需要新收据；计划文件可放本次临时位置。

`context update` 只为索引生成受限文件计划，沿用同一写入、收据与恢复机制。恢复索引只恢复对应文件版本，不恢复来源文档、不证明派生结论仍有效；恢复后仍要核对当前来源与受影响条目。

```sh
bun "/path/to/skill/scripts/main.ts" apply "/path/to/project" --plan "/path/to/plan.json" --receipt ".agents/state/bootstrap/adoption.json"
```

收据保存目标、修改前后摘要、恢复所需文本及各项实际状态。它是本机执行记录，不是新的项目事实源或授权。按实际报告核对已完成、未完成和未能确认的项；写入失败不等于所有文件都没变。

失败后先读取收据与当前文件，保留用户及其他会话的后续修改。需要继续初始化时，从当前状态生成剩余计划；不要只改旧计划摘要绕过冲突。需要撤销本轮文件修改时使用下节恢复入口。安装依赖、服务启动和外部写入由各自管理方式恢复，文件收据不撤销这些副作用。

收据保存完成不证明跨文件事务、任意崩溃恢复或所有编辑器并发安全。正常完成后按项目保留约定处置收据；清理前保存必要的脱敏交付证据。

## 恢复条件

```sh
bun "/path/to/skill/scripts/main.ts" recover "/path/to/project" --receipt ".agents/state/bootstrap/adoption.json" --dry-run
bun "/path/to/skill/scripts/main.ts" recover "/path/to/project" --receipt ".agents/state/bootstrap/adoption.json"
```

恢复也遵循当前用户授权和文件归属，不因收据存在增加权限。先确认目标项目与收据，再预检全部候选：

- 当前内容等于本轮写入结果时，可恢复修改前文本及对应文件属性。
- 当前已等于修改前内容时跳过，支持重复恢复。
- 本轮新建文件只在内容仍匹配本轮结果时删除，不批量删除目录。
- 当前内容、权限、文件类型或归属已变化时保留现场并报告冲突；预检冲突不恢复其他项。
- 收据为 `pending` 等未能确认完成的状态时保留现场；即使内容恰好匹配本轮目标摘要，也不能据此推定该项由本轮完成并自动恢复。
- 恢复中失败时保留收据和实际结果，重新读回核对；不通过旧备份批量覆盖后续工作。

单一文件的替换与读回不等于跨程序比较交换。并行编辑仍需明确文件归属；无法保证当前目标未被接管时先解决冲突。

恢复可能撤销本轮新增的忽略规则，收据仍会保留。后续交付或提交前，核对本机收据不会被带入交付内容。

## 冗余验收

按不同错误来源组合检查，不重复运行同一种检查冒充更多证据：

| 层次 | 核对对象 | 不能替代的结论 |
| --- | --- | --- |
| 静态结构 | 配置类型、路径、链接、引用、占位值和摘要 | 业务语义正确、依赖齐备 |
| 原始来源复核 | 用户目标、真实配置、代码路径与采用内容是否一致 | 实际运行成功 |
| 本机与业务运行 | 适用检查、真实链路、拒绝路径和必要回读 | 未覆盖平台、远端 CI 或发布成功 |
| 按风险独立验证 | 全新上下文能否找到规则、执行真实小任务并验证 | 自动调度、任意崩溃或所有项目均适用 |

资料矛盾保留双方证据，来源不可访问标明遗漏，服务不可用继续独立检查。无法安全应用时交付候选内容与缺口，不绕过保护或宣布环境已就绪。每一层分别记录输入、环境、实际结果和剩余风险。
