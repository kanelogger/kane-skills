## 材料选择

[资产清单](../assets/catalog.json) 保存逻辑 ID、物理文件、来源、推荐目标、策略和摘要。`asset` 是逻辑 ID，`file` 是相对技能 `assets/` 的实际路径，正文以 `.tmpl` 存放；读取时按清单的 `file` 定位，不把 ID 当文件路径。资产不是已适配的项目；选择子集或改变位置后核对引用。

| 策略 | 处理方式 |
| --- | --- |
| `copy` | 通用正文；规范适用、目标无冲突且引用齐全时以 `asset` 投放。已有同类规范则合并或引用。 |
| `adapt` | 含项目事实或源模板现状；结合真实配置、业务和约定生成最终 `content`。 |
| `optional` | 有对应需要才采用，并继续检查 `needs_adaptation`；保留填写模板和生成真实实例分开处理。 |

- **AGENTS**：保留适用个人约定和项目已有约束，改写真实定位、读取条件和导航。合并按需读取、来源变化重读、增量维护与工具缺失时直接读取的协议；不能只留一句“使用技能”。业务 README 只补开发入口。
- **project.yml**：从逻辑 ID `templates/docs/project.template.yml` 对应的材料和项目事实生成，实际文件位置读取清单的 `file`，不复制源模板根清单。版本和命令引用权威配置，未知不能写成空集合。
- **工程、测试与工作流**：复用项目实际检查和已有规则。把节点的上下文责任、风险触发的独立评审以及经验回写合并进实际工作流。根 AGENTS 提供可直接访问的入口，小项目可内联。
- **上下文索引**：初始化时建立或修复 `.agents/context/index.json`，指向现有工作流、至少一条真实检查命令和本次相关业务入口。内容保留在 `project.yml`、业务/子系统文档与任务或 Issue；新增派生结论才按需写 `.agents/context/derived/` 并登记源依赖。索引和稳定派生知识入库，不建立重复 `raw/` 或全局 `active_task`。
- **环境说明**：实际命令、服务、资源归属和验证边界能由环境清单和已有手册表达时，不再复制整套说明。
- **.gitignore** 保留顺序和例外，合并 `.agents/state/` 本机状态、任意目录下的 `.bootstrap-*.tmp` 及实际技术栈产物规则。已有 `.agents/` 忽略项要按当前规则处理例外，核对索引、稳定知识、示例、源码和交付证据仍可见。
- **角色、局部 AGENTS、子系统、任务和 ADR**：按实际分工、局部差异、稳定模块、接续或长期取舍建立，不为目录存在而建档。

## 接入结构

`verify TARGET --adoption` 要求根 `AGENTS.md`、根 `project.yml` 和 `.agents/context/index.json` 存在且有效。它检查这些入口、可达的工作流及经验库文档，以及各索引条目的来源、选择路径和已记录摘要。检查范围随已选的入口和索引变化，无需扫描其余项目文档。

- **工作流**：根 `AGENTS.md` 用标为“工作流”“开发工作流”或 `Workflow` 的相对 Markdown 链接指向实际文档。小项目可使用含正文的 `## 开发工作流` 或 `## Development workflow`。已有同义标签、标题或 `docs/workflow.md` 入口可沿用。工作流和其他内容共用 README 时，链接到工作流的标题锚点，或让 README 中的工作流标题可直接识别。
- **经验库**：从根 `AGENTS.md` 或其链接的工作流提供标为“经验库”或 `Lessons` 的相对 Markdown 链接。可使用自定义路径，也可链接项目内 Markdown 的具体锚点。沿用根 `LESSONS.md` 时可保留已有链接标签。
- **真实检查**：至少一条索引可解析到项目已定义的 test、check、lint、verify、validate、typecheck、format-check 等检查。可用 `select` 指向 `project.yml` 的 `environment.commands`、某条命令或其 `run`，也可选项目内 `package.json` 的 `scripts` 或其中一条脚本。名称由项目自定且无法按惯例识别时，用具体 `select` 并在 `when` 中加入 `verify`。

选择 `project.yml` 时，命令需填写 `run`、`working_directory` 和指向项目内实际定义文件的 `definition_source`。对于 `package.json`、`Makefile` 和 `Justfile`，工作目录要与定义所在目录一致，`run` 使用无额外参数的单条调用，例如 `npm run test` 或 `make check`。有额外参数时，可直接索引 `package.json` 中的对应脚本，或引用项目已有的脚本入口。其他本地检查用相对于工作目录的脚本路径作为调用入口，例如 `sh ./check.sh`。直接运行脚本时，该文件应具备可执行权限。

按链接所在文档换成项目实际相对路径。

```md
[工作流](docs/workflow.md)
[经验库](docs/development.md#项目经验)
```

## 经验库接入

1. 从目标项目的 AGENTS、工作流和已有文档确认经验库所在。复用已有的项目经验库及其记录约定，保留历史案例和证据。根目录 `LESSONS.md`、其他文档或其中的固定章节都可沿用。
2. 没有现成经验库时，将根目录 `LESSONS.md` 以最终 `content` 纳入操作计划。可参考逻辑 ID `templates/LESSONS.md` 的适配材料，写明查阅时机和交接记录格式。已有可追溯案例才写入本地记录，通用模式仅作排查参考，引用只保留实际可达的项目文档。
3. 按接入结构链接选定的经验库，在实际工作流的交接节点写明回写责任。工作流内联在 AGENTS 时，在同一文件覆盖查阅和交接写回职责。改写本次采用材料中指向默认 `LESSONS.md` 的链接及路径描述，使其指向项目实际位置。应用后运行 `verify TARGET --adoption`，并回读确认交接指向实际经验库且有明确的写回步骤。

## 操作计划

CLI 以 Bun 调用 `scripts/main.ts`。输入计划使用 UTF-8 JSON：

```json
{
  "schema_version": 1,
  "files": [
    {
      "path": "AGENTS.md",
      "expected_sha256": null,
      "content": "# 项目协作入口\n\n这里放已核实并合并完成的项目说明。\n"
    },
    {
      "path": "docs/git.md",
      "expected_sha256": null,
      "asset": "base/docs/git.md"
    }
  ]
}
```

示例仅说明格式，`base/docs/git.md` 是清单逻辑 ID。采用 Git 文档仍需提供或改写其工作流程引用；不能把示例当作完整接入方案。初始化计划还须纳入按实际来源生成的索引、入口协议和可达工作流；无需为它们增加包内 catalog 资产。

- `path` 相对明确的目标根目录，禁止绝对路径、`..`、Git 元数据路径和符号链接跳转。实际凭据、本机私有状态和 `.bootstrap-*.tmp` 不作为计划目标或内容来源。
- `content` 是最终全文，`asset` 是清单登记的逻辑 ID，只能选一项；CLI 不做语义合并。
- `asset` 必须已登记、摘要匹配且 `needs_adaptation: false`。可复制的填写模板仍是模板，实例化要另行填写事实。
- 新文件用 `expected_sha256: null`；修改现有文件用本轮 `inspect` 的摘要。目标已等于计划内容时跳过，其他差异保留现场。
- `apply --dry-run` 预检冲突和候选正文中的疑似凭据，覆盖将进入收据的旧正文。实际应用会重新核对，不把预检和原子替换视为跨编辑器的事务。
- 可选 `--context` 用于本轮来源和阻塞核对，格式见 `references/context.md` 的“本轮可选证据记录”。`--plan` 和 `--context` 可直接读取已有输入。保存技能本轮生成的文件前，按 `references/recovery.md` 的“写入前”审查并限制本机访问。
- 真正修改时在 `.agents/state/bootstrap/` 下保存收据。冲突和部分失败见 `references/recovery.md`。
- 目标已有上下文索引时，普通 `apply` 写后检查本轮变化文件关联的条目，结果放在 `context_updates`。待复核项不改写成功的文件结果，工具不自动刷新摘要或修改知识正文。

## 检查与运行边界

`inspect` 只读输出来源索引、摘要、候选命令名及示例变量名，不输出变量值或执行项目代码。`source_groups` 供 Agent 找到规则、配置、文档、测试、样例及历史入口；分组不证明已理解业务。

仅能可靠解析的来源提供候选命令，其他入口由 Agent 沿实际配置和开发说明读取。扫描有上限，截断、不可读和未解析都要保留缺口；没有候选不代表没有命令或不需要能力。

`verify` 检查协作入口、环境声明及发现的 Markdown；默认发现 `.agents/context/index.json` 时合并索引检查，`--paths` 限定范围时仅在显式选中索引后纳入。限定范围要明确未覆盖项。检查基本类型、来源路径、链接、锚点、重复配置键和实例中的明显填写提示。`null` 保留未知，手工操作说明及合法命令模板语法不作为 shell 执行。

初始化或修正接入应用后必须执行 `verify TARGET --adoption`，也可用于单独核对已有接入。`--adoption` 可和 `--context` 同用。要检查指定文件，另行调用 `verify --paths`。CLI 只核对结构、路径和引用。执行接入的 Agent 回读实际工作流，核实交接写回和独立评审规则适用，再按项目实际情况验证命令与业务行为。

静态检查始终不证明依赖完整、运行成功、客户端加载或业务正确。`--context` 可检查本轮证据记录结构和文件来源是否过期，与长期上下文索引无关；记录来源不证明来源说法真实，语义冲突和用户意图仍由 Agent 核实。`context` 子命令处理索引读取、来源变化与增量更新，不提供业务判断或项目命令执行器。

实际环境准备沿项目既有工具和锁文件，不顺带升级依赖或建立外部资源。根据真实入口核对程序参数、工作目录、前置条件、副作用、超时、取消与清理；CLI 不提供通用命令执行器，不直接运行环境清单中的自由文本。

## 资产维护

`catalog.json` 的 `source.snapshot_sha256` 按来源路径与实际打包正文的摘要计算。导出会为 `.gitignore` 保留技能需要的 `.bootstrap-*.tmp` 规则。包内资产可独立使用，初始化目标时不查找原仓库。

只有作者更新材料时，显式提供源目录运行：

```sh
bun "/path/to/kane-agent-bootstrap/scripts/sync-assets.ts" "/path/to/prototype-03" --check
```

去掉 `--check` 才导出更新。维护后核对快照、分类、链接和适配要求，不在两处手改同一资产正文。技能测试入口为 `bun test scripts/tests`，以技能目录为当前目录；独立复制后的可用性需单独验证。
