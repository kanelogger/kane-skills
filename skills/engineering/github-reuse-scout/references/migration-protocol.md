# 渐进迁移协议

fork 模式启动开发后，借用代码按本协议逐步迁移到目标框架。reference / none 模式迁移不适用。

## 借用单元清单（决策时生成）

从上游克隆树出发，按"一个可独立测试的行为单元"粒度划分借用单元（顶层模块 + 依赖清单 + 入口文件为线索）。
每单元记录：单元名、来源路径、状态（初始 `borrowed`）、迁移优先级、依赖的借用单元。

## 迁移优先级（确定性计算，清单生成时一次算好，迁移过程中不重算）

1. 按"该单元依赖的 borrowed 单元数"升序（叶子/依赖最少的先迁）；
2. 同级按体量升序（小单元先拿下）；
3. 同级有行为测试者优先。

## 每单元迁移步骤

1. 读借用实现与其测试，理解行为契约；
2. 在目标框架中实现等价行为，移植/新建行为测试（测试的是行为，不是上游的测试框架）；
3. grep 借用模块的全部引用，替换为新的目标框架实现；
4. 删除借用文件；
5. 运行测试确认通过；
6. 更新 `reuse-plan.md`：单元状态 → `ported`，迁移日志追加条目（日期、单元、动作、测试结果）。

## 节奏与边界

- 每会话迁移 1 个单元（硬默认）；用户明确要求更多时一次多个。
- 新功能一律用目标框架原生实现，不继续堆借用代码、不扩大借用面。
- 全部单元 `ported` → 迁移状态置为 `已完成`，向用户报告迁移完成。
- 目标框架为 `待确认` 时迁移挂起，只做正常开发；用户给出目标框架后从优先级为 1 的单元开始执行。
