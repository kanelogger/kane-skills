# requirement-explorer

引导业务专家完成结构化的需求探索，并生成标准的软件需求文档。

## 适用场景

- 把原始业务需求推进成结构化的需求文档。
- 开展交互式需求访谈与需求确认。
- 理清业务对象、业务功能、流程、审批规则、岗位角色、权限与数据可见范围。
- 为后续本体/建模工作准备需求材料。

## 输出

- 一份 Markdown 需求文档，包含场景/流程、业务功能与规则、业务对象、岗位角色、术语表和待澄清清单。
- 流程图与审批图使用 Mermaid 源码块。
- 依据内置需求规范完成的完整性检查；有未解决的企业特有问题时仅交付草稿，终稿也保留附录 B，无待确认项时写“无”。

## 输入与可选导出

提供原始业务需求，按阶段确认企业特有事实。提问优先使用运行时内置输入工具，缺失时回退到编号文本；没有原平台后端时用 Markdown 草稿与手工检查，不要求特定模型。

Markdown 交付后可选择 Word 导出，但仅在转换与渲染能力实际可用时执行。保留原 Markdown 的 Mermaid 源码，优先本地处理；向外部服务发送业务图表或文档前需单独确认。缺失工具时说明限制，不声称生成了 Word 文件。
