# verify-before-delivery

为智能体任务叠加与风险相称的验证围栏，用可复现证据代替“我确认没问题”。它先定义可检查的验收标准，
再按任务风险执行输出自检、事实核验、真实产物检查和独立复核。

## Use when

- 要求智能体证明任务真的完成，避免工具“假成功”。
- 希望在执行前定义验收标准，交付时逐项核验。
- 需要核验报告、调研、文件、代码、配置、表格或数据结果。
- 对外发布、正式提交或高代价任务需要独立复核和挑刺评审。

## Verification levels

| 等级 | 核心检查 |
| --- | --- |
| L1 | 输出格式与完整性自检 |
| L2 | 事实来源与待核实项 |
| L3 | 实际打开、运行、渲染或测试 |
| L4 | 新上下文独立核查 |
| L5 | 独立评审者主动找错并裁决 |

各层累积。能力不足时必须报告降级，不得声称达到未执行的等级。

## Examples

- `Use $verify-before-delivery to 修改这个配置，并给出实际运行证据。`
- `用 $verify-before-delivery 的 L2 检查这份报告，区分已验证和待核实内容。`
- `用 $verify-before-delivery 完成这份正式上报材料，并做独立复核。`

## Output

交付结果、产物位置、逐项验证证据、失败或未验证项，以及 L4/L5 场景下的独立复核结论。
