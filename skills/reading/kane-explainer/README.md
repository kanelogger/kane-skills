# kane-explainer

把文章、仓库、技术变更或当前讨论做成能独立读懂的视觉解释。根据你想弄懂的问题选择使用场景，再按读者基础决定讲多深。比如，互动教学也可以用一张结构图来总览整个流程。

此技能由用户显式调用。在 Codex 中输入 `$kane-explainer`，再说明要解释的材料和目标。

## 使用场景

| 场景 | 读者要做什么 | 交付物 |
| --- | --- | --- |
| 大图速懂 | 第一次接触主题，先看懂一个概念或场景 | 一张占主位的大图、短标签和少量说明组成的 HTML |
| 互动教学 | 跟着步骤动手，看到结果如何变化，再试一个新情形 | 有进度、操作反馈、重试和理解检验的教学网页 |
| 结构图解 | 看清系统分工、调用路径、事件影响或前后变化 | 按需选用关系图、时序图、目录树或短伪代码等。需要截图分享或内联图难以表达时，做 HTML 信息图或迷你幻灯片 |

## 使用示例

### 大图速懂

> 请用 kane-explainer 做一个大图少字的 HTML 组件，给第一次听说本地优先应用的人讲清为什么断网时仍能修改任务。

### 互动教学

> 把《Reverse Engineering Linear’s Sync Engine》做成给初学者的互动教学网页。用“修改任务标题”串起几步，让我亲手切换离线、改标题、恢复网络，观察两端各自看到什么，最后让我预测一个新情形的结果。 [示例文章](https://github.com/wzhudev/reverse-linear-sync-engine)

### 结构图解

> 请用结构图解画出一次 RAG 问答的数据流。标出用户问题、检索、原文片段和模型之间的关系，以及模型在什么时候读到原文。

结构图解也可以用来画一次产品更新涉及的角色和可能的影响、排查项目的调用路径、梳理 AI 工具每一步在哪里操作，或整理一组概念的依赖。需要配图时，可以直接补一句“做成一张适合截图的 HTML 信息图”。

## 交付

提供原文链接、本地文件或要解释的会话范围，再补充读者基础和想弄懂的问题。默认用中文。HTML 默认交付可直接打开的单个文件，核心图文和交互可以离线使用。涉及技术变更时，图解会交代影响理解的前后行为、数据格式和兼容边界。
