# 结构图解

1. 写下这次图解要回答的问题。沿一件事或一份数据走一遍，确认相关角色、边界、方向和先后顺序。只留下理解这条路径需要的关系，把可能的影响或推断与已知事实分开标注。
2. 按读者要看懂的关系选表达形式。优先用对话中就能读懂的图或短代码结构。一个视图能讲清时就用一个，只有读者需要切换视角时才增加视图。

| 要看懂什么 | 选用形式 | 图中交代什么 |
| --- | --- | --- |
| 机制、算法或条件 | 流程图或决策层伪代码 | 输入、判断条件、分支结果 |
| 协作、运行时调用或数据流 | 时序图、数据流图或调用树 | 谁发出什么、谁处理、顺序与去向 |
| 系统、项目或组件结构 | 架构图、组件树或浅层目录树 | 职责、归属、跨边界依赖 |
| 版本、状态或行为变化 | 前后对照或局部 diff | 同一场景里发生变化的位置和后果 |
| 新闻、产品更新或行业事件 | 时间线或关系图 | 背景、角色、已发生的事和可能的影响路径 |
| AI 工具或多步工作流 | 分阶段流程图 | 每步在哪里做、需要什么、产物如何进入下一步 |
| 一组内容、概念或知识 | 概念图或分组树 | 层级、依赖或交叉关系 |

3. 需要截图传播、并排比较视觉状态，或关系密度超出内联图的承载能力时，交付聚焦单一主题的 HTML 信息图或迷你幻灯片。截图所需信息应在画面中完整可见，标题、标签和结论离开对话也成立。
4. 从读者的起点走到图上的结论，检查每条关键连线能否用一句话说清。收起解释文字后，图仍能回答起始问题，并保留会改变结论的条件或边界。
