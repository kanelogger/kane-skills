# 求职方向映射

把用户可证明的价值与岗位需求对齐。先收集工作经历、能力与成果、可用资源、学历和行业背景、地域、薪酬及时间约束、偏好与不可接受条件。已有价值点资产库可直接使用；没有时从原始经历提取最小事实集。

## 映射

1. 将证据归为能力、资源、背景三类标签。资源只写用户确实拥有且可合法使用的客户关系、渠道或行业经验；不把雇主资产视作个人资源。
2. 提出候选岗位和细分方向，写明每个方向需要的核心标签、用户已有证据、差距及补证途径。
3. 对跨越幅度做比较：同业转岗、同岗转业、同时转岗转业。后者通常需要更多新证据，但不能机械排除；看实际 JD 和可验证项目。
4. 在用户有可用外部信息时核查近期 JD、招聘数量和变化；需要当前市场判断时检索真实招聘来源并标明地区、日期、样本范围。没有现时证据就写“需求趋势未验证”，不套用“热门行业”或固定年龄结论。

当目标与旧岗位跨度大时，用“旧任务 → 可迁移能力 → 新岗位任务 → 缺少的证据”四列拆解，而不是把旧岗位改名。缺少目标岗位实绩时，优先设计一个小而真实的验证项目：明确问题与使用者、完成可展示产物、记录反馈与迭代，并标清它是个人/练习项目还是正式工作。具体路径见 [跨岗验证样例](references/transition-paths.md)；不要照搬样例中的职业结论。

区分用户“想做”和“有机会被录用”。尊重兴趣和生活约束，不仅按市场价值排序。产品经理等职业的案例只可作类比，不把任何个人经验总结当作入行门槛。

## 交付

通常给 2 至 3 个优先方向；若证据仅支持一个或多于三个，就如实给出。每个方向用表格列：具体岗位与行业、匹配证据、核心差距、验证动作、外部需求证据、优先级理由。最后给一个低成本验证计划，例如查看若干真实 JD、访谈从业者或完成与岗位相关的可展示项目，并说明何时调整方向。
