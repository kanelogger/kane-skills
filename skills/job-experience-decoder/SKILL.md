# 经历价值解码

目标是得到与特定 JD 无关、可复用且可核验的价值点，而不是把每段经历都写得耀眼。处理用户提供的履历、项目材料或口述；缺少关键信息时提出少量具体追问，同时先产出已有部分。

## 拆解方法

对每段经历记录 STAR：情境与约束、本人承担的任务、本人做出的关键行动或判断、结果。区分团队成果与个人贡献。结果进一步检视四层：

| 层次 | 要找的证据 |
|---|---|
| R1 具体结果 | 交付了什么，改变了什么 |
| R2 数据与口径 | 数值、基准、周期、数据来源；没有就明确缺失 |
| R3 业务影响 | 对客户、团队或业务的实际作用，说明因果证据的强弱 |
| R4 可迁移能力 | 哪个动作证明了什么能力，能够迁移到哪些任务 |

四层不是强制填满的模板。无法核实的数字、影响或因果关系标为待补证，不替用户猜。失败、规模小或支持性岗位也可提取价值：看约束下的判断、执行、学习和可复用方法，保留结果的真实边界。

没有上线、增长或最终交付时，继续追问：项目停在哪一步、本人做过哪些判断和推进、遇到什么约束、留下了什么可检查的中间产物、失败原因哪些已证实。把“验证了什么”和“尚未验证什么”分开写；不能把参与融资沟通写成促成融资，也不能把团队决定写成本人主导。遇到创业、边缘实习或多年同岗经历时，可读 [经历样例](references/experience-cases.md) 找追问角度，不套用其中的结论。

将抽象特质改成可识别的事实入口，例如用一次判断与行动说明“洞察力”。合并重复记述；暂缺证据的独立事实标为待补证，不因当前没有明确目标岗位而删去。资产库保留原始事实及出处，是否与某岗位相关、是否对外突出，留到目标方向或 JD 确定后判断。空窗和其他敏感事实不必主动堆在价值点里；被直接问到时如实回答。

## 交付格式

每条价值点给出：经历 ID、STAR 摘要、R1 至 R4 已知内容、证据来源、已核实与待补证部分、待追问项，以及一句仅使用已核实事实的候选表述。按经历或能力主题整理，标记证据状态；不在 JD 无关的资产库里分“高价值/暂不突出”。样例只用于启发，不把创业、名企实习或多年同岗经历自动判为优势。
